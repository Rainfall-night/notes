## 🧭 推荐的设计模式学习路径（按阶段分组）

### ✅ 第一阶段：**创建型模式**（掌握对象如何被创建）

> 👉 跟单例模式类似，都是负责“**对象的创建过程**”

| 模式名        | 学习重点                           |
| ---------- | ------------------------------ |
| **单例模式**   | ✅ 已掌握                          |
| **工厂方法模式** | 多个子类由工厂创建，解耦创建逻辑               |
| **抽象工厂模式** | 生产一系列产品（多个相关对象），适合产品族          |
| **建造者模式**  | 复杂对象一步步构建，如链式调用、Lombok builder |
| **原型模式**   | 对象复制（浅拷贝 vs 深拷贝）               |

---

### ✅ 第二阶段：**结构型模式**（掌握类和对象如何组合）

> 👉 重点是“**类之间的组合结构**”，解决的是扩展性、灵活性

|模式名|学习重点|
|---|---|
|**适配器模式**|让两个接口不兼容的类能一起工作（老系统升级）|
|**装饰器模式**|动态扩展功能（比继承更灵活，如 I/O 流）|
|**代理模式**|控制访问、加日志、懒加载（静态代理 vs 动态代理）|
|**桥接模式**|多维度变化解耦（实现和抽象分离）|
|**外观模式**|为复杂系统提供统一的接口（如 Spring Facade）|
|**组合模式**|树形结构如菜单、文件夹|
|**享元模式**|重复对象共享（减少内存），如连接池、对象池|

---

### ✅ 第三阶段：**行为型模式**（掌握对象间如何交互）

> 👉 重点是“**对象之间的通信协作规则**”

|模式名|学习重点|
|---|---|
|**策略模式**|多种行为封装为策略类，如排序策略|
|**模板方法模式**|固定流程 + 可变步骤，使用继承扩展|
|**观察者模式**|发布-订阅机制（事件驱动）|
|**状态模式**|状态变化引起行为改变（如订单状态流转）|
|**责任链模式**|多个处理器组成链条（如过滤器链）|
|**命令模式**|封装请求（支持撤销、队列）|
|**中介者模式**|对象之间不直接通信，通过中介协调|
|**备忘录模式**|保存历史状态（如撤销功能）|
|**解释器模式**|解析特定语法或表达式|
|**迭代器模式**|提供统一方式遍历集合|
|**访问者模式**|分离算法和对象结构|

---

那么下一步建议如下：

1. **工厂方法模式**（使用频率高、实际应用多）
    
2. **抽象工厂模式**（对比理解与工厂方法的区别）
    
3. **策略模式**（行为型入门，和工厂结合使用很多）
    
4. **模板方法模式**（Spring 源码常见）
    
5. **代理模式**（动态代理、AOP 基础）
    
6. **装饰器模式**（增强类行为，常用于 I/O）
