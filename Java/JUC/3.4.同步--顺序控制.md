# wait() / notify() 方式实现顺序控制
**注意点:**
1. 此段代码维护一个`private volatile int[] flag;`作为令牌桶，flag大小为交替打印的线程数，每轮到一个线程时，其对应的 `flag[i]` 会被置为 1 ，其余则置为 0 （这里为本人的自我尝试，询问ai后，此处在极端条件或有其他与打印线程相关的线程时，可能会产生死锁的问题）
2. 针对 “ 1 ” 中可能存在的问题，建议使用 `private volatile int current = 0;` 单一令牌，防止。。。（我也不清楚上面说的问题到底会怎么触发...）

```java
@Slf4j  
public class WaitNotify {  
  
    // 交替打印线程数  
    private int threadNum;  
  
    // 交替打印次数  
    private int times;  
  
    // 锁  
    private final Object lock = new Object();  
  
    private volatile int[] flag;  
  
    public WaitNotify(int threadNum, int times) {  
        this.threadNum = threadNum;  
        this.times = times;  
        this.flag = new int[threadNum];  
        Arrays.fill(this.flag, 0);  
    }  
  
    public void print() {  
        flag[0] = 1;  
  
        for (int j = 0; j < threadNum; j++) {  
            // 将 j 数值记录为隐式final以便在thread块中使用  
            final int threadID = j;  
            new Thread(() -> {  
                int count = 0;  // 打印次数记录器
                // 获得锁  
                while (count < times) {  
                    synchronized (lock) {  
                        // 自己当前的flag为0，则说明没轮到自己  
                        while (this.flag[threadID] == 0) {  
                            try {  
                                lock.wait();      //睡觉  
                            } catch (InterruptedException e) {  
                                Thread.currentThread().interrupt();  
                                return;                            }  
                        }  
  
                        // 干活，打印自己的值  
                        log.info("Thread-{}: {}", threadID, threadID + 1);  
  
                        //将自己的flag设置为0，准备睡觉  
                        this.flag[threadID] = 0;  
                        this.flag[threadID + 1 < threadNum ? threadID + 1 : 0] = 1;  
                        lock.notifyAll();  
                        count++;  
                    }  
                }  
  
            }, "Thread-" + j).start();  
        }  
    }  
}
```

# await() / signal() 方式实现顺序控制
**注意点:**
1. 这种方法似乎没什么好主意的，就是相比上一种需要为每个线程创建一个 `Condition` 桶，使用起来似乎内存占用会多一些，但在线程唤醒的控制粒度上会更小
2. 此处使用了上文提到的 `private volatile int current = 0;` 作为令牌

```java
@Slf4j  
public class AwaitSignal {  
    // 全局锁对象  
    private final Lock lock = new ReentrantLock();  
  
    // 交替打印的线程数  
    private final int threadNum;  
  
    //交替打印的次数  
    private final int times;  
  
    // 线程休眠Condition桶  
    private Map<String, Condition> conditionMap = new HashMap<>();  
  
    private volatile int current = 0;  
  
    public AwaitSignal(int threadNum, int times) {  
        this.threadNum = threadNum;  
        this.times = times;  
  
        // 给每个线程创建一个对应的Condition  
        for (int i = 0; i < this.threadNum; i++) {  
            this.conditionMap.put("Thread-" + i, lock.newCondition());  
        }  
    }  
  
    public void print() {  
        for (int i = 0; i < threadNum; i++) {  
            final int threadID = i;  
  
            new Thread(() -> {  
                int count = 0;  
                while (count < times) {  
                    lock.lock();  
                    try {  
                        while (current != threadID) {  
                            // 这个似乎只有线程刚创建时运行一次  
                            // 线程不满足运行条件就去休眠  
                            try {  
                                conditionMap.get("Thread-" + threadID).await();  
                            } catch (InterruptedException e) {  
                                Thread.currentThread().interrupt();  
                                return;                            }  
                        }  
  
                        // 干活，打印自己的值  
                        log.info("Thread-{}: {}", threadID, threadID + 1);  
  
                        // 切换线程 0 1 2                        current = (current + 1) % threadNum;  
                        conditionMap.get("Thread-" + current).signal();  
  
                        count++;  
                    } finally {  
                        lock.unlock();  
                    }  
                }  
            }, "Thread-" + i).start();  
        }  
    }  
}
```

# park() / unpark() 方式实现顺序控制
**注意点：(这个注意点有点多...)**
1. park() / unpark()仅用作对线程状态的控制，并==不会对线程中的锁产生影响==（park后该又锁还是会有锁，不注意释放锁的话极其容易产生死锁）
2. 这个问题在上面两种方式中也可能会出现：当前线程打印完自己的线程后唤醒下一个线程时，下一个线程可能还没被创建，此时可能会出现无法唤醒对应线程死锁或本案例中的 `thread[] threads` 对应线程为空从而空指针异常的问题 (**注：**后面发现上面两个似乎不会出现线程没创建从而无法唤醒的问题，因为线程一旦被创建就会运行，而一旦运行就必定会有线程满足运行下去的条件，从而不会死锁)
	1. 针对这个问题，参考ai的建议，加入了 `CountDownLatch` 线程计数器，在每次线程创建好后，就进行一次计数，创建完所有线程后再由主线程开启第一个线程
	2. 在这种情况下，`private volatile int current = 0;` 应该一开始被设置为不能使任何线程继续运行下去的条件

```java
@Slf4j  
public class ParkUnpark {  
  
    // 全局锁对象  
    private final Lock lock = new ReentrantLock();  
  
    // 交替打印的线程数  
    private final int threadNum;  
  
    //交替打印的次数  
    private final int times;  
  
    private volatile int current = 0;  
  
    private Thread[] threads;  
  
    private CountDownLatch latch;  
  
    public ParkUnpark(int threadNum, int times) {  
        this.threadNum = threadNum;  
        this.times = times;  
        this.threads = new Thread[threadNum];  
        this.latch = new CountDownLatch(threadNum);  
    }  
  
    public void print() {  
        for (int i = 0; i < threadNum; i++) {  
            final int threadID = i;  
  
            threads[i] = new Thread(() -> {  
                // 计数  
                latch.countDown();  
  
                int count = 0;  
                while (count < times) {  
                    while (current != threadID) {  
                        // 不满足运行条件，进入休眠  
                        // park() 不会释放锁，线程进入WAITING状态，但仍保持已获取的锁资源 
                        // 因此在这个案例中，current的检查不放入锁之中，不清楚这样会有什么不可预料的后果 
                        //此处可以放入锁代码块中，但在park前需要先解锁，那后边就需要先进行一次加锁再运行，不然可能会产生解锁异常
                        LockSupport.park();  
                    }  
                    
                    lock.lock();  
                    try {  
  
                        // 被唤醒后，干活，打印自己的值  
                        log.info("Thread-{}: {}", threadID, threadID + 1);  
  
                        // 切换线程  
                        current = (current + 1) % threadNum;  
                        LockSupport.unpark(threads[current]);  
  
                        count++;  
                    } finally {  
                        lock.unlock();  
                    }  
                }  
            }, "Thread-" + i);  
            threads[i].start();  
        }  
  
        try {  
            latch.await();  
        } catch (InterruptedException e) {  
            throw new RuntimeException(e);  
        }  
    }  
}
```
