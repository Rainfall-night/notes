# 多把锁
> 可以通过加多把锁，细化锁粒度来增强并发度，但使用多把锁时需要**注意死锁现象**

```java
@Slf4j  
public class BigRoom {  
	//两个锁对象
    private final Object studyRoom = new Object();  
    private final Object bedRoom = new Object();  

	//每个操作只使用一种锁
    public void sleep() {  
        synchronized (bedRoom) {  
            log.debug("sleeping 2 小时");  
            Thread.sleep(2000);  
        }  
    }  
  
    public void study() {  
        synchronized (studyRoom) {  
            log.debug("study 1 小时");  
            Thread.sleep(1000);  
        }  
    }  
}
```

# 线程活跃性
> 线程活跃性相关问题基本总结为**死锁、活锁与饥饿**，这些是因为资源竞争和调度策略不当导致的线程无法正常执行的情况。它们各自有不同的特点和产生机制。

## 死锁
> **死锁**是指两个或多个线程在执行过程中，因争夺资源而造成的一种互相等待的现象。

### 死锁产生条件
死锁的发生需要**同时满足**以下四个必要条件：

1. **互斥条件 (Mutual Exclusion)**：至少有一个资源是不能被共享的，即一次只能被一个线程使用。
2. **请求与保持条件 (Hold and Wait)**：一个线程已经持有至少一个资源，但又试图去获取另一个被其他线程持有的资源，同时不释放自己已经持有的资源。
3. **不剥夺条件 (No Preemption)**：已经分配给一个线程的资源不能被强制性地从该线程中抢夺，只能由持有它的线程自愿释放。
4. **循环等待条件 (Circular Wait)**：存在一个线程链，其中每个线程都在等待下一个线程所持有的资源。

### 避免死锁的方法
要避免死锁，只需破坏以上四个条件中的**任意一个或多个**即可。

- **破坏互斥条件**：通常不可行，因为有些资源本身就是互斥的（如打印机）。
- **破坏请求与保持条件**：
    - **一次性申请所有资源**：线程在开始执行前，一次性请求它所需的所有资源。如果不能全部获得，就一个也不拿。缺点是资源利用率低，可能导致饥饿。
    - **持有资源时不允许申请新资源**：线程在持有资源时，如果需要更多资源，必须先释放所有当前持有的资源，然后再重新申请所需的所有资源。
- **破坏不剥夺条件**：
    - 当一个线程请求的资源被占用时，可以强行剥夺其持有的资源（如果允许）。
    - 例如，线程请求资源失败时，可以释放自己已持有的资源。
- **破坏循环等待条件**：
    - 对资源进行**排序**，并规定线程必须按照资源的固定顺序来获取。例如，总是先获取资源 A，再获取资源 B。这样就能避免形成环路。
    - 例如：
```java
// 线程1
synchronized (lockA) {
    synchronized (lockB) {
        // ...
    }
}

// 线程2
// 如果也按 A -> B 顺序获取，就不会死锁
synchronized (lockA) {
    synchronized (lockB) {
        // ...
    }
}
```

## 活锁
> **活锁**是指线程没有被阻塞，但由于某种原因（比如结束条件始终被修改、过于“礼貌”或过于频繁地响应对方的动作），导致它们一直在尝试做某事，但却**无法取得任何实质性进展**的状态。它们不断地改变自身状态，但始终无法突破当前困境.

### 特点：
- 线程处于**运行状态**（而不是阻塞状态）。
- 线程**不断地尝试**某个操作。
- 操作**总是失败**，导致线程循环往复，**无法完成任务**。

### 常见场景：
- **互相谦让**：两个线程都想获取资源，但当发现对方也想要时，为了避免冲突而主动放弃，导致双方都不断放弃，谁也拿不到资源。
- **忙循环重试**：线程在执行失败后，立即重试，但条件未变，导致一直失败重试。

### 避免活锁的方法：
- **引入随机性**：在重试或放弃前引入随机等待时间，或引入退避策略（backoff strategy）。
- **优先级调整**：设计更合理的竞争策略，避免无意义的互相谦让。

## 饥饿
> **饥饿**是指一个或多个线程在竞争资源时，因**优先级太低**、**调度不公平**或**资源分配策略不当**等原因，长时间得不到执行，或者总是无法获取到所需的资源，从而导致任务迟迟无法完成。

### 特点：
- 线程**没有死锁**，也没有活锁。
- 线程可能处于就绪状态，但**长时间得不到 CPU 时间片**。
- 线程可能在等待资源，但**总是被其他线程抢占**。

### 常见原因：
- **优先级问题**：高优先级线程不断抢占 CPU，导致低优先级线程长时间无法运行。
- **调度器不公平**：调度器偏爱某些线程，或采用非公平的资源分配策略。
- **活锁的极端情况**：虽然线程不断尝试，但由于其他线程的活动，导致它总是失败，这可以看作是饥饿的一种形式。
- **资源无限循环获取**：某个线程不断获取并释放资源，导致其他线程很难有机会获取到资源。

### 避免饥饿的方法：
- **保证调度公平性**：使用公平锁（如 `ReentrantLock(true)`），确保等待时间最长的线程优先获得资源。
- **调整线程优先级**：合理设置线程优先级，避免某些线程长时间得不到执行（但过度依赖优先级容易引入复杂性）。
- **避免长时间持有资源**：设计算法时，尽量缩短线程持有资源的时间。
- **退避和重试策略**：对于竞争失败的线程，采用退避策略，等待一段时间再重试，给其他线程机会。
