> `ReentrantLock` 是 `java.util.concurrent.locks` 包中提供的一个**可重入的互斥锁**，它实现了 `Lock` 接口（**这是一个类，而不是关键字**）。其核心实现依赖于 **AQS (AbstractQueuedSynchronizer)** 框架，AQS 负责管理同步状态和等待线程队列。

# 主要特性
## 1. 可重入
- **定义：** 同一个线程在已经获得锁的情况下，可以**再次**获取该锁，而不会导致死锁。每次重入都会增加锁的计数器，直到计数器归零时，锁才真正被释放。
- **实现：** `ReentrantLock` 内部维护一个计数器 (`state`)，每次获取锁时计数器加 1，每次释放锁时减 1。只有当计数器为 0 时，锁才对其他线程可用。
```java
class ReentrantLockReentrancy {  
  
    private final ReentrantLock lock = new ReentrantLock();  
  
    public void outerMethod(){  
        lock.lock();  
        try {  
            log.info("outerMethod第一次获取锁");  
            innerMethod();  
        }finally {  
            log.info("outerMethod解锁");  
            lock.unlock();  //ReentrantLock不会自动解锁，必须要手动解锁  
        }  
    }  
  
    private void innerMethod(){  
        lock.lock();  
        try {  
            log.info("innerMethod第二次获取锁");  
        }finally {  
            log.info("innerMethod解锁");  
            lock.unlock();  
        }  
    }  
  
    public static void main(String[] args) {  
        ReentrantLockReentrancy reentrancy = new ReentrantLockReentrancy();  
		//相当于在同一个主线程中获取了两次lock，此时并不会报错
        reentrancy.outerMethod();  
    }  
}
```

## 2.可中断
- **定义：** 线程在**等待获取 `ReentrantLock` 的过程中**，可以响应中断。如果线程在调用 `lockInterruptibly()` 方法等待锁时被中断，它会抛出 `InterruptedException`，从而允许线程退出等待状态并处理中断逻辑。
- **对比 `synchronized`：** `synchronized` 在等待锁时是不可中断的，线程会一直阻塞直到获取锁或程序结束
```java
class ReentrantLockInterruptibility {  
  
    private final ReentrantLock lock = new ReentrantLock();  
  
    public void accessResource(){  
        try {  
            lock.lockInterruptibly();  
            try {  
                log.info("{}获取锁",Thread.currentThread().getName());  
                Thread.sleep(5000);     //模拟使用耗时  
            } finally {  
                log.info("{}释放锁锁",Thread.currentThread().getName());  
                lock.unlock();  
            }  
  
        } catch (InterruptedException e) {  
            log.warn("{}线程发生{}",Thread.currentThread().getName(),String.valueOf(e));  
  
        }  
    }  
  
  
    public static void main(String[] args) throws InterruptedException {  
        ReentrantLockInterruptibility interruptibility = new ReentrantLockInterruptibility();  
  
        Thread t1 = new Thread(interruptibility::accessResource, "t1");  
        Thread t2 = new Thread(interruptibility::accessResource, "t2");  
        // 模拟t1先获取锁  
        t1.start();  
        Thread.sleep(1000);  
        t2.start();  
  
        // 此时t2会进入阻塞状态，模拟t2在等待时被打断  
        Thread.sleep(2000);  
        t2.interrupt();  
  
        t1.join();  
        t2.join();  
  
        log.info("结束");  
    }  
}
```

## 3.锁超时
+ 锁超时是指一个线程在尝试获取锁时，可以**指定一个最长等待时间**。如果在规定时间内成功获取了锁，它会继续执行；如果超时仍未获取到锁，它就会放弃等待，并从 `lock()` 方法返回一个 `false` 值，或者抛出异常。
+ **`tryLock` 与 `lockInterruptibly` 的区别**
	- **`tryLock(long timeout, TimeUnit unit)`**：在指定时间内等待。超时后，**方法返回 `false`**。如果被中断，会抛出 `InterruptedException`。
	- **`lockInterruptibly()`**：无限期等待，但可以**响应中断**。当线程被中断时，它会抛出 `InterruptedException` 异常，而不会返回 `false`。
	- 简而言之，`tryLock` 主要关注“超时”，而 `lockInterruptibly` 主要关注“中断”。

```java
class ReentrantLockTimeout {  
  
    private static final ReentrantLock lock = new ReentrantLock();  
  
    public static void main(String[] args) {  
        Thread t1 = new Thread(() -> {  
            log.info("{}-try to get lock", Thread.currentThread().getName());  
  
            // tryLock()不加参数代表不等待，加入参数表示最大等待时间  
            // tryLock() 超时为获得锁会返回false  
            // tryLock()超时等待时被打断会抛 InterruptedException            try {  
                if (!lock.tryLock(2000, TimeUnit.MILLISECONDS)) {  
                    log.info("{}-fail to get lock", Thread.currentThread().getName());  
                    return;                }  
            } catch (InterruptedException e) {  
                log.error("{}-thread got some error",Thread.currentThread().getName());  
                log.error("error message -- {}",e.getMessage());  
                throw new RuntimeException(e);  
            }  
  
            try {  
                log.info("{}-thread get the lock",Thread.currentThread().getName());  
            } finally {  
                lock.unlock();  
            }  
  
        }, "t1");  
  
        lock.lock();  
        log.info("{}-thread get the lock",Thread.currentThread().getName());  
        t1.start();  
  
        try {  
            Thread.sleep(1000);  
        } catch (InterruptedException e) {  
            throw new RuntimeException(e);  
        }finally {  
            lock.unlock();  
        }  
    }  
}
```

## 4.公平性
- **定义：** `ReentrantLock` 可以选择公平锁或非公平锁。
    - **非公平锁（默认）：** 线程获取锁的顺序是**不确定的**。新来的线程可以“插队”，直接尝试获取锁，无需排队等待，通常提供更高的吞吐量。
    - **公平锁 (`new ReentrantLock(true)`)：** 线程获取锁的顺序是**先进先出 (FIFO)** 的。当锁被释放时，AQS 等待队列中等待时间最长的线程将优先获得锁，有效避免了饥饿现象，但可能牺牲部分性能。
- **实现区别：**
    - **非公平锁**的 `lock()` 方法会先尝试通过 CAS 直接获取锁（“插队”），失败才进入 AQS 队列。
    - **公平锁**的 `lock()` 方法会**先检查 AQS 队列是否有等待线程** (`!hasQueuedPredecessors()`)，如果有，即使锁空闲也会老实排队，只有队列为空或当前线程是队首时才尝试获取。

## 5.绑定多条件对象
- **定义：** `ReentrantLock` 提供了 `newCondition()` 方法来创建 `Condition` 对象。**每个 `Condition` 对象相当于一个独立的等待队列**。线程可以调用 `Condition.await()` 在特定条件下等待，并调用 `Condition.signal()` 或 `Condition.signalAll()` 精确唤醒该 `Condition` 队列中的线程。
- **对比 `synchronized`：** `synchronized` 只能使用 `Object.wait()/notify()/notifyAll()`，它们共享同一个等待队列，无法实现更细粒度的线程分组唤醒。`Condition` 弥补了这一不足，使得生产者-消费者等复杂协作模式的实现更加灵活和高效。
```java
// 此部分仅作演示，ReentrantLock的Condition在多线程任务中有明显的优势，但此处生产者线程与消费者线程仅各有一个
class ReentrantLockCondition {  
    private final ReentrantLock lock = new ReentrantLock();  
    private final Condition producerCondition = lock.newCondition();  
    private final Condition consumerCondition = lock.newCondition();  
    private Integer shareBuffer = null;  
  
    public void produce(Integer value) throws InterruptedException {  
        lock.lock();  
        try {  
            while (shareBuffer != null) {  
                log.info("缓存桶为满，生产者等待");  
                producerCondition.await();  
            }  
            shareBuffer =value;  
            log.info("生产者生产缓存，唤醒一个消费者");  
            consumerCondition.signal();  
        } finally {  
            log.info("生产者解锁");  
            lock.unlock();  
        }  
    }  
  
    public void consumer() throws InterruptedException {  
        lock.lock();  
        try{  
            while(shareBuffer == null){  
                log.info("缓存桶为空，消费者等待");  
                consumerCondition.await();  
            }  
            int value = shareBuffer;  
            shareBuffer =null;  
            log.info("消费者消费-{}",value);  
            producerCondition.signal();  
        }finally {  
            log.info("消费者解锁");  
            lock.unlock();  
        }  
    }  
  
    public static void main(String[] args) throws InterruptedException {  
  
        ReentrantLockCondition condition = new ReentrantLockCondition();  
  
        Thread producerThread = new Thread(() -> {  
            for (int i = 0; i < 10; i++) {  
                try {  
                    condition.produce(i);  
                    Thread.sleep(5000);  
                } catch (InterruptedException e) {  
                    throw new RuntimeException(e);  
                }  
            }  
        },"producer");  
  
        Thread consumerThread = new Thread(() -> {  
            for (int i = 0; i < 10; i++) {  
                try {  
                    condition.consumer();  
                    Thread.sleep(3000);  
                } catch (InterruptedException e) {  
                    throw new RuntimeException(e);  
                }  
            }  
        },"consumer");  
  
        producerThread.start();  
        consumerThread.start();  
  
        producerThread.join();  
        consumerThread.join();  
    }  
}
```
