# 03 · 文件生命周期与提交

> 相关笔记:[[01-核心概念与架构]] · [[02-获取与初始化]] · [[04-历史对比与撤销]] · [[09-易错点与学习路线]]

## 1. Git 文件状态机

```
Untracked(新文件) →(git add)→ Staged(已暂存) →(git commit)→ Committed(已提交)
Committed →(修改)→ Modified(已修改) →(git add)→ Staged(循环)
```

## 2. SVN 文件状态机

```
Unversioned(? 新文件) →(svn add)→ Added(A) →(svn commit)→ Committed
Committed →(修改/删除/移动)→ Modified(M)/Deleted(D)/Missing(!) →(svn commit)→ Committed
```

## 3. 操作对照

| 场景 | Git | SVN |
|---|---|---|
| 查看状态 | `git status` / `-s` | `svn status` / `-q` |
| 添加新文件 | `git add 文件` | `svn add 文件` |
| 修改后提交 | `git add` + `commit` | **直接 `svn commit`** |
| 提交 | `git commit -m "msg"` | `svn commit -m "msg"` |
| 删除 | `git rm 文件` | `svn delete 文件` |
| 移动/重命名 | `git mv 旧 新` | `svn move 旧 新` |
| 提交指定文件 | `git commit 文件 -m` | `svn commit 文件 -m` |

## 3.5 Git add 的多种形式(SVN 无暂存区,粒度不同)

Git 的暂存区让 `add` 有很细的粒度;SVN **没有暂存区**,也没有"交互式选一部分"的概念。

```bash
# Git
git add .                     # 当前目录及子目录所有改动
git add -A                    # 整个仓库所有改动(含删除)
git add mock/user.js          # 单个文件
git add src/views/            # 整个目录
git add -p                    # 交互式逐块确认,只提交部分改动(SVN 无对应)

# SVN 对应
svn add 新文件                 # 只有"新文件"才需要 add
svn commit 某文件 -m "msg"     # 只提交指定文件(近似 Git 的"只提交一部分")
```

> `git commit -am "msg"` = 跳过 add,直接把所有**已跟踪**文件 add + commit;SVN 改旧文件本来就直接 commit,天然等价,不用此参数。

## 4. 易踩坑(必看)

| 场景 | Git | SVN |
|---|---|---|
| 改旧文件不 add 直接 commit | 报错 | ✅ 正常 |
| 新建文件不 add 直接 commit | 报错 | ⚠️ 提交不包含它,必须**先 `svn add`** |

> SVN 里看到 `?` 的新文件 = 还没进版本库,`svn add` 后才会被 commit 跟踪。

## 5. 状态标记速记

| SVN 标记 | 含义 | Git 对应 |
|---|---|---|
| `?` | 未纳入版本的新文件 | untracked |
| `A` | 已 add 待提交 | staged(新文件) |
| `M` | 已修改 | modified |
| `D` | 已删除 | deleted |
| `C` | 冲突 | conflicted |
| `!` | 文件缺失 | 无对应 |
