# 07 · 高级功能

## 一、Git 独有功能

### 1. 暂存工作现场 stash
```bash
git stash                    # 藏起所有未提交改动,工作区变干净
git stash save "改了一半的样式" # 存起来并加描述,方便识别
git stash list               # 查看存了哪些
git stash pop                # 取出最近一条并删除(恢复到工作区)
git stash apply              # 取出但不删除(可多次应用到不同分支)
git stash drop               # 丢弃最近一条
```
典型场景:在 feature 分支改到一半,突然要切到 main 修 bug → `git stash` → 切分支修 bug → 切回来 → `git stash pop`。

> **SVN 没有 stash**——没有本地暂存/草稿。改到一半要切换只能:① 先 commit 到当前分支;② `svn revert` 丢弃(不可恢复);③ 复制一份工作副本。

### 2. 变基 rebase

**rebase = "变基" = 改变你提交的"基座(基础点)"。**

假设你在 `main` 的 `A` 点拉了分支 `feature`,做了两个提交 `C1`、`C2`;后来同事把 `main` 推进到了 `B`:

```
main:    ...── A ── B
feature:      A ── C1 ── C2      ← feature 落后于 main
```

`git rebase main`(在 feature 上执行)= 把 `C1`、`C2` 从 `A` 上"拔下来",重新"种"到最新的 `B` 上:

```
main:    ...── A ── B
feature:            B ── C1' ── C2'   ← 重放,内容一样但 hash 变了
```

结果:历史变成**一条直线**,看起来就像从最新 main 开始开发——这就是"历史干净"。

**底层三步**:① 找共同祖先 `A` → ② 收集 `A` 之后的提交 `C1`/`C2` → ③ 目标前进到 `B` 后**逐个重放**(hash 全变)。

**两种最常用场景:**

```bash
# 场景 A:分支落后,把 main 最新代码并进来(保持线性)
git checkout feature
git rebase main

# 场景 B:日常拉取远程更新(最常用)
git pull --rebase origin main
# 普通 git pull = fetch + merge(多一个合并节点);--rebase = fetch + rebase(线性)
```

**rebase 遇冲突**——和 merge 不同,它是**逐个提交重放**,所以一次只处理一个提交的冲突:

```bash
git rebase main
# 重放 C1 时撞冲突,Git 停下提示冲突文件
# ① 手动删冲突标记,保留想要的代码
git add 冲突文件
git rebase --continue        # ② 继续重放下一个提交(C2),又冲突就重复
# 全部重放完 → rebase 完成

# 中途想放弃:
git rebase --abort           # 回到 rebase 之前,一切恢复
```

> ⚠️ 改完冲突**一定要 `git add` 再 `--continue`**,否则报错。

**merge vs rebase:**

| | `git merge` | `git rebase` |
|---|---|---|
| 历史形状 | 保留真实分叉,多一个合并节点 | 线性,无分叉 |
| 提交 hash | 不变 | 变了(重放) |
| 冲突处理 | 一次性全给你 | 逐个提交处理 |
| 安全性 | 不改写历史,安全 | 改写历史,有风险 |
| 适合 | 大功能、长期分支、多人协作 | 个人分支、拉取更新、整理本地 |

> ⚠️ **不要 rebase 已经 push 到远程的提交**——rebase 会改写提交 hash,别人若基于旧提交继续开发,历史就乱了。只 rebase 本地还没 push 的提交。**SVN 没有 rebase,只有 merge。**

### 3. 精选提交 cherry-pick
```bash
git cherry-pick <提交哈希>   # 把某提交的改动复制到当前分支
```

### 4. 后悔药 reflog
```bash
git reflog             # 查看 HEAD 所有移动记录
git reset --hard <哈希> # 找回误删的提交
```
**SVN 没有 reflog,revert 错了就真没了。**

### 5. 二分定位 bug bisect
```bash
git bisect start
git bisect bad       # 当前有 bug
git bisect good <旧哈希>  # 标记正常版本
# Git 自动二分,定位引入 bug 的提交
```

### 6. 子模块 submodule
```bash
git submodule add <url> 路径   # 嵌套其他仓库
```

## 二、SVN 独有功能

### 1. 文件属性 propset
```bash
svn propset svn:ignore "bin" .                    # 忽略规则
svn propset svn:mime-type image/png 图片           # MIME 类型
svn propset svn:keywords "Date Revision" file.cs  # 关键字自动替换
svn propget svn:ignore .                          # 查看
svn propedit svn:ignore .                         # 编辑
svn proplist -v .                                 # 全部属性
```

### 2. 文件锁定 lock(防二进制冲突)
```bash
svn lock file.bin -m "我在改这个资源文件"
svn unlock file.bin
```
适用:二进制/大资源文件无法合并时,用锁防止两人同时改。

### 3. 外部引用 externals
```bash
svn propset svn:externals "^/libs/common common" .
```
类似 Git submodule,引用其他目录/仓库代码。

### 4. 仓库与发布
```bash
svnadmin create /路径/myrepo   # 建库(管理员)
svn list <url>                 # 列出目录
svn info                       # 工作副本信息(版本号/URL)
svn export <url>               # 导出不带 .svn 的干净副本(发布用)
svn cleanup                    # 清理中断操作留下的锁
```
