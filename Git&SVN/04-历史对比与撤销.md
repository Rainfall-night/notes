# 04 · 历史、对比与撤销

> 相关笔记:[[03-文件生命周期与提交]] · [[05-分支合并与标签]] · [[09-易错点与学习路线]]

## 1. 查看日志 log

```bash
# Git
git log --oneline                 # 一行一条
git log -5                        # 最近5条
git log --author="张三"           # 按作者
git log --since="2026-01-01"      # 按时间
git log --grep="bug"              # 按信息搜索
git log -p <文件>                 # 某文件每次提交的 diff
git log --graph --oneline --all   # 图形化分支图

# SVN
svn log -l 10                     # 最近10条
svn log -v                        # 显示改了哪些文件
svn log -q                        # 精简
svn log --search "bug"            # 按信息搜索
svn log <文件>                    # 某文件历史
```

## 2. 对比差异 diff

```bash
# Git
git diff                    # 工作区 vs 暂存区
git diff --cached           # 暂存区 vs 上次提交(--staged 是它的别名)
git diff HEAD               # 工作区所有改动 vs 上次提交
git diff HEAD~1 HEAD        # 两个提交之间
git diff 分支A 分支B         # 两个分支之间

# SVN
svn diff                    # 本地改动 vs 上次更新
svn diff -r 120:125         # 两个版本
svn diff -r 120 file.txt    # 某文件旧版本 vs 当前
svn diff --summarize        # 只列哪些文件有差异
```

## 3. 逐行溯源 blame

```bash
git blame file.txt
svn blame file.cs     # 逐行显示 谁/哪个版本 改的
```

## 4. 撤销未提交的改动

```bash
# Git —— 推荐新写法 restore(专管"恢复文件")
git restore file.txt                  # 撤销工作区改动,回到上次 commit
git restore .                         # 全部
git restore --staged file.txt         # 把已 add 的文件从暂存区撤回工作区(替代 git reset HEAD)
git restore --source=HEAD~1 file.txt  # 从指定 commit 恢复某个文件
# 老写法 checkout(身兼多职)
git checkout -- file.txt              # 等价 git restore file.txt
git checkout HEAD~1 -- file.txt       # 等价 --source 写法

# SVN(无暂存区,没有 --staged / --source 这些概念)
svn revert file.txt
svn revert -R .                       # 递归整个目录
```
> ⚠️ `svn revert` **不可恢复**,SVN 没有 reflog。

## 5. 撤销已提交的改动

### Git 的 reset 三种模式对比

| 模式 | commit | 暂存区 | 工作区 | 安全性 | SVN 对应 |
|---|---|---|---|---|---|
| `--soft` | 撤销 | 保留 | 保留 | ✅ 最安全 | 无(无法撤销已提交历史) |
| `--mixed`(默认) | 撤销 | 清空 | 保留 | ✅ 安全 | 无 |
| `--hard` | 撤销 | 清空 | 清空 | ⚠️ 不可恢复 | 无 |

`HEAD~1` = 回退 1 次 commit,`HEAD~3` = 回退 3 次;SVN 里对应的是**全局版本号**,如 `-r 120`。

```bash
# Git
git reset --soft HEAD~1    # 撤销 commit,改动保留在暂存区
git reset --mixed HEAD~1   # 撤销 commit,改动保留在工作区(默认)
git reset --hard HEAD~1    # 彻底删除 commit 和代码(危险!)
git revert <哈希>           # 新增一条反向提交,安全、不抹历史

# 修改最近一次提交(不新增 commit)——SVN 无此概念
git commit --amend -m "新提交信息"   # 改上次 commit 的信息
git commit --amend --no-edit        # 把暂存区改动追加到上次 commit,不改信息

# SVN(历史改不了,只能反向合并)
svn merge -r 125:120 .     # 反向改动合并到工作副本
svn commit -m "回退r125"    # 提交回退(历史留两条记录)
```

**核心区别**:Git 能 reset"抹掉本地历史重写";SVN 历史在服务器上不可改,只能反向合并再提交。

## 6. 查看旧版本代码

```bash
git checkout <哈希>          # 临时切到某提交(detached HEAD)
git checkout <哈希> -- 文件   # 拿某文件旧版本

svn update -r 120            # 工作副本回到 r120
svn cat -r 120 file.txt      # 输出 r120 的某文件内容(不动工作副本)
```
