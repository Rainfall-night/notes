# 01 · 核心概念与架构

> 相关笔记:[[00-总览-MOC]] · [[03-文件生命周期与提交]] · [[05-分支合并与标签]]

## 1. 两者的本质区别

| | Git | SVN |
|---|---|---|
| 类型 | **分布式** | **集中式** |
| 完整历史存在哪 | 每个克隆的仓库都有 | 只在服务器 |
| 本地 | 完整仓库 | 只是"工作副本"快照 |
| 能否离线 | 几乎全部操作可离线 | 提交/更新/历史都要联网 |
| 版本标识 | 40 位哈希 `a1b2c3d` | 递增整数 `r123` |
| 存储方式 | 快照流 | 变更集(差异) |

一句话:**Git 像"每个员工都带着公司完整账本",SVN 像"只有财务部一本总账,员工手里只有自己的拷贝"。**

### 粒度差异:为什么说 Git 的"粒度"更高

**粒度 = 操作能精细到什么程度。** Git 把"提交"拆成 **工作区 → 暂存区 → 本地库 → 远程库** 四层,每一层都能单独精细操作;SVN 只有 **工作副本 → 服务器** 两层,要么做要么不做。

| 层面 | Git | SVN |
|---|---|---|
| 暂存 | 有暂存区,还能 `add -p` 逐块选择只提交部分 | 无暂存区,只能全提或指定文件 |
| 提交 | 本地可提交任意次,攒着一次性 push | 一提交就上服务器 |
| 历史修改 | `amend` / `rebase -i` 可重排、合并、拆分 | 历史不可动,只能追加 |
| 分支 | 指针,随便开/切/删 | 目录拷贝,重、慢 |
| 撤销 | 精确到文件 / 暂存区 / 提交 / 单个提交 | 整文件 revert 或整段反向合并 |
| 挑选 | `cherry-pick` 精确复制某个提交 | 无 |
| 临时 | `stash` 随时存草稿 | 无 |

**双刃剑:**

| | 粒度高(Git) | 粒度低(SVN) |
|---|---|---|
| 灵活性 | ✅ 极高 | ❌ 基本没有 |
| 学习成本 | ❌ 高 | ✅ 低 |
| 误操作风险 | ❌ 高(`reset --hard` / `push -f` 都危险) | ✅ 低(历史几乎改不了) |
| 复杂度 | ❌ 高 | ✅ 简单直白 |

> **根源**:分布式(本地也有完整历史,才能精细操作)vs 集中式(历史只在服务器,只能粗粒度操作)。

## 2. Git 的三大区域

```
工作区(Working Directory)
   │ git add
   ▼
暂存区(Staging/Index)
   │ git commit
   ▼
本地仓库(Local Repo) ── git push ──▶ 远程仓库(Remote)
```

- 工作区 = 磁盘上的文件
- 暂存区 = 中间层,`git add` 放进来
- 本地仓库 = `git commit` 记录到 `.git`
- 远程仓库 = `git push` / `pull` 同步对象

## 3. SVN 的两层结构

```
服务器版本库(Repository) ← 唯一权威
   │ svn checkout / svn update
   ▼
本地工作副本(Working Copy)
   │ svn commit
   ▼
(回到服务器)
```

SVN **没有暂存区、没有本地提交**。改完要么 commit(上服务器),要么丢弃。

## 4. 安装与配置

### 安装
- Git:git-scm.com,Windows 自带 Git Bash
- SVN:Windows 用 **TortoiseSVN**(图形界面)或 SlikSVN(命令行)

### 身份配置
```bash
git config --global user.name "张三"
git config --global user.email "zhangsan@company.com"
git config --global --list
svn commit -m "msg" --username zhangsan   # SVN 用服务器账号,无需本地配置
```

> SVN 身份是服务器账号统一管理;Git 的 user.name 只是提交记录上的签名。

## 5. 版本号体系

- Git:哈希(内容寻址),`git log` 显示长串
- SVN:全局递增整数 r120、r125,**整个仓库统一编号**,回滚/对比用 `-r 120:125`
