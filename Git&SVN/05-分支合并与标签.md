# 05 · 分支、合并与标签

> 相关笔记:[[01-核心概念与架构]] · [[04-历史对比与撤销]] · [[06-远程协作与忽略]] · [[07-高级功能]] · [[09-易错点与学习路线]]

## 1. 分支概念差异

| | Git | SVN |
|---|---|---|
| 分支本质 | 指向提交的指针,几乎零成本 | **目录的物理拷贝**,成本高 |
| 创建 | `git branch 名` / `git checkout -b 名` | `svn copy <url>/trunk <url>/branches/名` |
| 切换 | `git checkout 名` / `git switch 名` | `svn switch <url>/branches/名` |
| 合并 | `git merge 名` | `svn merge <url>/branches/名` |
| 删除 | `git branch -d 名` | `svn delete <url>/branches/名 -m` |
| 推荐用法 | 随便开、频繁开 | 少用,改动小走主线 |

### Git 的 switch vs checkout

Git 2.23 把 `checkout` 拆成了 `switch`(切分支)和 `restore`(恢复文件),各司其职,新手更好懂。

| | `git checkout` | `git switch` |
|---|---|---|
| 切换分支 | ✅ | ✅(推荐) |
| 创建并切换 | `checkout -b` | `switch -c`(推荐) |
| 恢复文件 | ✅ `checkout -- 文件` | ❌ 不支持(用 `git restore`) |
| 语义 | 身兼多职,容易搞混 | 只做一件事:切换分支 |

```bash
git switch feature/login       # 切换到已有分支
git switch -c feature/login    # 创建并切换(推荐替代 checkout -b)
git switch -                   # 切回上一个分支
git branch -D feature/login    # 强制删除(不管是否已合并)
git branch -a                  # 本地 + 远程分支
git branch -r                  # 只列远程分支
```

> **SVN 对应**:`svn switch <url>` 只负责把工作副本切到另一个 URL(分支);SVN 没有"恢复文件"这种分支操作,恢复文件用 `svn revert`。

## 2. SVN 的目录布局(必懂)

```
https://svn.company.com/repo/
├── trunk/            # 主干 = 稳定版本 ≈ master
├── branches/         # 功能/发布分支
│   ├── feature-login/
│   └── release-1.0/
└── tags/             # 发布标签 = 只读快照
    └── v1.0/
```

**SVN 的分支就是复制一份目录,没有"指针"概念。**

## 3. 分支操作对照

```bash
# Git
git checkout -b feature/login
git add . && git commit -m "xxx"
git checkout main
git merge feature/login
git branch -d feature/login

# SVN
svn copy <url>/trunk <url>/branches/feature-login -m "建分支"
svn switch <url>/branches/feature-login
svn commit -m "xxx"
svn switch <url>/trunk
svn merge <url>/branches/feature-login
svn commit -m "合并完成"
svn delete <url>/branches/feature-login -m "删分支"
```

> 💡 SVN 里 **update 是"把服务器合并到自己这边"**,**merge 是"把别的 URL 的差异合并进来"**,两者别混。

## 4. SVN冲突解决

冲突 = 你和同事改了**同一文件同一行**。合并/更新时,工具不知道该用谁的,就报冲突。

### 4.1 冲突是怎么发生的

```
你:  基于 r123 拉取代码 → 修改 file.cs
同事:在服务器提交 r124(也改了 file.cs 同一处)
你:  svn update ──▶ SVN 要合并 r124,发现和你的改动撞在同一行 → 冲突
```

> SVN 的 `update` 是"把服务器新提交**合并进你的工作副本**",不是覆盖。改到**不同地方**会自动合并;只有改到**同一行/同一块**才会冲突。

### 4.2 冲突时生成的三个文件(保险设计)

`svn update` 报冲突后,冲突文件旁会**多出 3 个文件**,含义分别是:

| 文件 | 真实含义 | 类比 Git |
|---|---|---|
| `file.cs` | 冲突后的文件本体(内部有冲突标记) | 冲突文件 |
| `file.cs.mine` | **你的版本**(你改过的) | `HEAD` 侧 |
| `file.cs.r123` | **基础版本**(冲突前的共同起点) | `merge base` |
| `file.cs.r124` | **服务器最新版本**(同事提交后的) | 对方分支 |

> ⚠️ 注意:**`file.r123` 是基础版本,`file.r124` 才是服务器版本**。SVN 不敢替你决定用谁的,所以把"你的 / 基础 / 服务器"三份全部保留,任何一方都不被覆盖。

打开冲突文件 `file.cs`,能看到**冲突标记**:

```
<<<<<<< .mine
你的代码
=======
>>>>>>> .r124
同事的代码
```

### 4.3 三种解决方式

**方式一:手动编辑(学习时必会)**
1. 打开 `file.cs`,看到 `<<<<<<< .mine` 标记
2. 手动决定保留谁的代码(或两者都保留)
3. **删掉 `<<<<<<<` / `=======` / `>>>>>>>` 标记行**,保存

**方式二:TortoiseSVN 图形化(实战推荐)**
右键冲突文件 → **Edit conflicts**,打开三栏对比窗口(左=你的 `.mine` / 中=基础 `.r123` / 右=服务器 `.r124`,底部=最终结果),鼠标点选要保留的块,所见即所得。

**方式三:命令行直接裁决(不想细看时)**
```bash
svn resolve --accept=working file.cs      # 采用你的版本
svn resolve --accept=theirs-full file.cs  # 采用服务器(同事)的版本
svn resolve --accept=base file.cs         # 采用基础版本
```

### 4.4 svn resolve 的作用(关键!)

**解决完文件还不够,必须执行 `svn resolve`**——它告诉 SVN"这个冲突我处理完了",把文件从"冲突(C)"状态清除,变回"已修改(M)"。**不 resolve 就不能 commit 这个文件。**

### 4.5 完整流程

```bash
svn update                                # ① 更新,报冲突
# 出现 file.cs + file.cs.mine + file.cs.r123 + file.cs.r124
# ② 解决:手动编辑 / TortoiseSVN / --accept 三者选一
svn resolve file.cs                       # ③ 标记已解决(必须!)
svn commit -m "解决冲突"                    # ④ 提交
```

### 4.6 与 Git 冲突对比

| | Git | SVN |
|---|---|---|
| 触发时机 | `git merge` / `git pull` | `svn update` / `svn merge` |
| 冲突标记 | `<<<<<<< HEAD` … `>>>>>>> 分支` | `<<<<<<< .mine` … `>>>>>>> .r124` |
| 额外文件 | 无(信息都在冲突标记里) | `.mine` / `.rOLD` / `.rNEW` 三个 |
| 解决标记 | `git add` 即算解决 | **必须 `svn resolve`** |
| 提交 | `git commit` | `svn commit` |

## 5. 标签 Tags

| | Git | SVN |
|---|---|---|
| 打标签 | `git tag v1.0` | `svn copy <url>/trunk <url>/tags/v1.0 -m "发布"` |
| 带注释 | `git tag -a v1.0 -m "说明"` | 同上 |
| 查看 | `git tag` | `svn list <url>/tags` |
| 推远端 | `git push --tags` | 无需(拷贝即在服务器) |
| 回退到标签 | `git checkout v1.0` | `svn update -r <版本号>` |

> SVN 的 tag 是目录拷贝,约定只读;Git 的 tag 是不可变对象。
