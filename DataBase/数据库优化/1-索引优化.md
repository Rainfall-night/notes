# 索引优化

> **所属**：[[0-数据库优化总览]] ｜ **下一篇**：[[2-SQL优化]]

## 1. 索引是什么、为什么快

- 索引本质是 **B+ 树**：数据组织成多层节点，查一行 = 走树深（约 3~4 次 IO），而不是扫全表
- **没有索引 = 全表扫描 = 灾难**；亿级表查询快慢，几乎全看有没有对的索引

## 2. 索引类型


| 类型                               | 说明                                                      |
| ------------------------------------ | ----------------------------------------------------------- |
| **主键索引**                       | 唯一 + 聚簇（MySQL）/ 默认聚簇（SQL Server）              |
| **唯一索引**（UNIQUE）             | 业务唯一键，如`WorkOrderCode`                             |
| **联合/复合索引**                  | 多列组合，见[[#5. 联合索引设计（最左前缀）]]                                              |
| **二级索引**                       | 普通非聚簇索引                                            |
| **列存储索引** Columnstore（进阶） | 亿级**聚合**（SUM/COUNT/透视表）场景 10~100x，值压缩+列式 |
| **函数/表达式索引**（进阶）        | MySQL 8 / SQL Server 计算列 / PostgreSQL 表达式索引       |
| **筛选索引** Filtered（进阶）      | SQL Server 专属，带`where` 子句只索引部分行               |
| **全文 / 空间索引**（进阶）        | 全文检索 / 地理空间查询                                   |

## 3. 聚簇 vs 非聚簇（先消歧）

- **聚簇索引 = 聚集索引**（同一个概念 `Clustered`，只是中文翻译打架）
- **非聚簇 = 非聚集 = 二级/辅助索引**（`Nonclustered / Secondary`）


|        | 聚簇 Clustered                        | 非聚簇 Nonclustered               |
| -------- | --------------------------------------- | ----------------------------------- |
| 本质   | 数据物理顺序 = 索引顺序，叶子就是整行 | 独立索引树，叶子存"索引列 + 书签" |
| 数量   | 一张表只能 1 个                       | 可多个                            |
| 找到后 | 就是数据本身                          | 要**回表**                        |
| 类比   | 字典按拼音排（正文即索引）            | 部首检字表（目录指向页码）        |

**MySQL vs SQL Server 差异**：


|              | MySQL InnoDB                   | SQL Server                                  |
| -------------- | -------------------------------- | --------------------------------------------- |
| 聚簇         | 强制有（主键），表结构天然如此 | 可选；不建就是堆表 Heap                     |
| 二级索引书签 | 存**主键值**                   | 有聚簇→聚簇键；堆表→**RID**（文件:页:行） |
| 注意         | —                             | 堆表行移动会留"转发指针"，回表可能更差      |

## 4. 回表 & 覆盖索引

- **回表**：二级索引找到书签 → 再读一次数据页（命中 Buffer Pool 则无真实磁盘 IO）
- **覆盖索引**：索引已包含查询要的所有列 → 不回表 → 最快
  - SQL Server：`INCLUDE (col)` 追加额外列
  - MySQL：把列并进联合索引
- **别 `select *`**：查大字段（如日志的 `Content`）必然回表

## 5. 联合索引设计（最左前缀）

- **第一列必须在**；**全等值时优化器自动重排，SQL 书写顺序无关**（`a,c,b`、`b,c,a` 都一样）
- **等值列在前，范围列（BETWEEN）放最后；范围列后的列失效**
- **`between` 支持索引**（等价 `>= and <=` 范围扫描）——不是它让索引失效
- **真正失效场景**：范围列后断档 / **函数包裹索引列**（`YEAR(col)`）/ **隐式转换**（`id='123'`）/ 前通配 `LIKE '%x%'`

## 6. 索引选择性与列选择

- **选择性** = 去重值占比（distinct/总行数），越高越好
- 同是等值列，**高选择性列放前**（过滤更多行）
- 别在低选择性列建索引（如"性别"），收益低

## 7. 查询写法与索引（进阶）

- **in / or**：一般能走索引；**not in / not exists** 可能全表扫描（注意）
- **order by**：索引列顺序与排序方向一致 → 免额外排序（filesort/sort）
- **索引下推（ICP）**（MySQL 5.6+）：`where` 条件下推到索引层，减少回表

## 8. 页分裂 & 索引碎片

- **页分裂**：页满时插中间 → 拆两页 → 插入慢、空间碎片、索引碎片
- **逻辑碎片**（页内数据乱序）与**物理碎片**（页空洞）都会拖慢范围扫描/顺序读
- **维护**：`alter index ... rebuild`（重建）/ `REORGANIZE`（重组）
- **Fill Factor（填充因子）**：预留页内空间（如 90=留 10% 空）减少页分裂，但浪费空间，需权衡

## 9. 主键选择：自增 vs UUID

- **自增**：追加插入、免页分裂、顺序写 IO、二级索引小（BIGINT 8B）
- **UUID**：中间随机插、频繁页分裂、16B 使二级索引更大
- **例外**：分布式/分库分表不能用自增（多库撞号）→ 用**雪花算法**（趋势递增 + 全局唯一）

## 10. 索引的代价

- **写放大**：每个索引都拖慢 insert/update/delete
- **占用空间**
- **冗余索引**：相同前缀的索引重复 → 该删（别贪多，按真实高频查询建 2~3 个）

## 11. 发现缺索引 / 冗余索引

- **执行计划**：SSMS Ctrl+M 开「实际执行计划」，找 **Table Scan（表扫描）** → 缺索引
- 系统建议：`select * from sys.dm_db_missing_index_details;`（SQL Server 缺索引 DMV）
- MySQL 排查：`explain select ...` 看执行计划 `type` 列（`all`=全表扫，`ref`/`range`/`index`=走了索引）；`show index from 表名` 看已有索引
- 冗余索引排查：`sys.dm_db_index_usage_stats`

## 12. 索引的物理存储

- 存储层级：MySQL 页16KB→区1MB→段→表空间；SQL Server 页8KB→区64KB→文件组
- **页**是 B+ 树节点，行存在页里；**区**是空间分配单位（一次分配一片连续页，保证顺序 IO）
- 相关：[[#8. 页分裂 & 索引碎片|页分裂]]

## 13. 针对本场景的索引建议

### `tbl_WorkOrder`（千万级）

```sql
-- 业务唯一键点查（工单号）
create unique index IX_WorkOrder_WorkOrderCode on tbl_WorkOrder(WorkOrderCode);
-- 高频筛选：State（等值）+ CreateTime（范围，放最后）
create index IX_WorkOrder_State_CreateTime on tbl_WorkOrder(State, CreateTime);
```

### `tbl_WorkOrderLog`（亿~十亿级）★核心

```sql
-- 按工单查流水（GetWorkOrderLog，时间倒序）
create index IX_WorkOrderLog_WorkOrderID_ModifyTime
    on tbl_WorkOrderLog(WorkOrderID, ModifyTime desc);
-- 覆盖索引：按 工单+工序+操作 取最新一条（GetLatestLogRow / 老化机台监控）
create index IX_WorkOrderLog_WorkOrder_Op23
    on tbl_WorkOrderLog(WorkOrderID, Operate2, Operate3, ModifyTime desc);
```

> ⚠️ `Content` 是大 JSON 字段，**别放进索引**（保持回表即可）。
