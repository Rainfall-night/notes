# 表分区

> **所属**：[[0-数据库优化总览]] ｜ **上一篇**：[[2-SQL优化]] ｜ **下一篇**：[[4-归档与冷热分离]]

## 1. 什么是表分区

**逻辑上是一张表，物理上按"分区函数/方案"切成多段**，放不同文件组：

```
tbl_workorderlog（逻辑一张表）
├── 分区1：modifytime < 2025-01-01   → 文件组 A
├── 分区2：2025-01-01 ~ 2025-03-31   → 文件组 B
└── ...（按月切）
```

对应用**完全透明**——CRUD 一行代码不用改，数据库自动路由到对应分区。

**分区 vs 分表**：


|          | 分区               | 分表           |
| ---------- | -------------------- | ---------------- |
| 逻辑对象 | 1 张表（一个映射） | N 张物理表     |
| 谁来路由 | 数据库内部自动     | 应用/中间件做  |
| 应用感知 | 完全无感           | 要感知路由规则 |

## 2. 🔴 分区的真实价值定位

**分区不是"查询加速"方案，是"超大表运维/管理"方案**：


| 价值          | 说明                                                                   |
| --------------- | ------------------------------------------------------------------------ |
| ① 超大表维护 | 删除/归档旧数据**秒级**（分区切换），不用 `delete` 亿行（会锁表+慢死） |
| ② 分区裁剪   | 查询**带分区键**时只扫对应分区                                         |

**关键认知**：

- **点查单行** → 分区**不直接加速**，还是靠索引（方案①）
- 分区键必须**参与查询条件**才谈得上"分区裁剪"
- 查询加速靠索引，分区的重点是"能维护亿级表"

## 3. 跨数据库（收费差异）


| 数据库     | 表分区                                         |
| ------------ | ------------------------------------------------ |
| SQL Server | ⚠️ 仅**Enterprise（收费）**，Standard 不支持 |
| Oracle     | ⚠️ 收费（独立 License）                      |
| MySQL      | ✅ 免费（InnoDB）                              |
| PostgreSQL | ✅ 免费（10+ 声明式分区）                      |
| SQLite     | ❌ 不支持                                      |

## 4. 分区类型

- **range（范围）**：最常用，按数值/时间切（如按月）——日志表首选
- **list（列表）**：按离散值切（地区/状态）
- **hash（哈希）**：按哈希均匀分布（无自然范围时）
- **key**（MySQL）：按主键哈希

## 5. 分区裁剪 vs 索引（两层协作，索引照建）

**两层分工，不是二选一**：

```
① 分区裁剪（粗粒度）：决定扫哪几个分区（按分区键）
② 索引（细粒度）：在目标分区内精确定位（Index Seek）
```

- **分区是表级切片**（按维护/归档维度，通常是时间）
- **索引是切片内定位**（按查询维度，通常是 workorderid）
- **两者互补，都要建**；分区不能替代索引

## 6. 分区索引（主键 vs 二级索引）

分区表上的索引，逻辑上还是一个索引对象，物理上按分区**切成 N 棵子树**（自动"对齐分区"）。


| 索引类型             | 自动建？               | 分区表上     |
| ---------------------- | ------------------------ | -------------- |
| **主键（聚簇）索引** | ✅ 自动（InnoDB 机制） | 自动对齐分区 |
| **二级/非聚簇索引**  | ❌ 手动`create index`  | 建了自动对齐 |

**⚠️ 唯一索引/主键必须包含分区键**（否则无法对齐，MySQL 直接报错）：

```sql
-- ❌ 报错：分区键 modifytime 不在主键里
create table t (
    id bigint not null,
    modifytime datetime not null,
    primary key (id)
) partition by range (year(modifytime)) (...);

-- ✅ 正确：主键改成联合主键，包含分区键
create table t (
    id bigint not null,
    modifytime datetime not null,
    primary key (id, modifytime)
) partition by range (year(modifytime)) (...);
```

## 7. range left vs right（边界归属）

**left/right 决定"边界值本身算左还是算右"**：

- **range left**：边界值归**左**分区（`<= 边界` 在左）
- **range right**：边界值归**右**分区（`>= 边界` 在右）

边界 `'2025-01-01','2025-02-01','2025-03-01'`：

```
range left（边界归左）：
  分区1: <= 2025-01-01
  分区2: > 2025-01-01 且 <= 2025-02-01
  分区3: > 2025-02-01 且 <= 2025-03-01

range right（边界归右）：
  分区1: < 2025-01-01
  分区2: >= 2025-01-01 且 < 2025-02-01   ← 正好一个自然月（1月）
  分区3: >= 2025-02-01 且 < 2025-03-01
```

**时间分区推荐 `range right`**（边界=每月1日，每分区正好一个自然月）。
**MySQL 的 `values less than (边界)` 固定是 range right 语义**，没有 left/right 选项。

## 8. 分区切换（秒级归档核心）

```sql
-- sql server：把"分区2"整段秒级挪到归档表（不搬数据，只改元数据）
alter table tbl_workorderlog switch partition 2 to archive_workorderlog;
```

- **秒级**完成（改元数据，不搬数据）
- 归档旧分区、装载新数据都靠它
- 这是分区**最大的价值**：删旧数据从小时级 → 秒级

## 9. SQL Server 分区语法（Enterpris）

```sql
-- ① 分区函数：定义边界
create partition function pf_log_month (datetime)
as range right for values
('2025-01-01','2025-02-01','2025-03-01','2025-04-01','2025-05-01','2025-06-01');

-- ② 分区方案：把分区映射到文件组
create partition scheme ps_log as partition pf_log_month all to ([primary]);

-- ③ 建分区表（分区键 = modifytime）
create table tbl_workorderlog_part (
    id bigint not null,
    workorderid bigint not null,
    modifytime datetime not null
) on ps_log(modifytime);

-- ④ 加新分区：先 next used 再 split
alter partition scheme ps_log next used [primary];
alter partition function pf_log_month() split range('2025-07-01');
```

## 10. MySQL 分区语法

```sql
-- range 分区（按月），分区键必须在主键/唯一键里
create table tbl_workorderlog (
    id bigint not null,
    workorderid bigint not null,
    modifytime datetime not null,
    primary key (id, modifytime)          -- ⚠️ 必须含分区键
) partition by range (year(modifytime)) (
    partition p2024 values less than (2025),
    partition p2025 values less than (2026),
    partition p2026 values less than (2027),
    partition pmax values less than maxvalue
);

-- 删旧分区（秒级归档）
alter table tbl_workorderlog drop partition p2024;

-- 加新分区
alter table tbl_workorderlog add partition (
    partition p2027 values less than (2028)
);
```

**MySQL 注意**：分区数上限 8192；range 分区 `null` 归最小分区；表达式可用 `year()` 等但列有限制。

## 11. 注意事项

- 分区键要**参与查询**，否则裁剪失效
- **分区不是索引替代**：每个分区内该建索引照建
- 分区数别过多（上千有元数据开销）
- **唯一索引/主键必须包含分区键**（MySQL 硬性）
- SQL Server 先确认是否 **Enterprise**，不是则跳过此方案

## 12. 针对本场景

- `tbl_workorderlog` 按 `modifytime` 按月 **range** 分区 + **分区切换**归档一年前数据 → 在线表体量骤减
- `tbl_workorder`（千万级）**不需要分区**，索引就够
