# 数据库优化总览

> **适用场景**：`tbl_WorkOrder`（千万级）+ `tbl_WorkOrderLog`（亿~十亿级，工序/器件日志）
> **定位**：数据库优化整体方案索引，按"从最便宜到最贵"排序

## 核心原则

**分库分表是最后手段，不是第一选择。** 1.1 亿行大部分靠「索引 + SQL 优化 + 分区 + 归档」就能解决；分库分表带来的复杂度（分布式事务、全局 ID、跨库 join、扩容）可能比原问题大十倍。

## 优先级建议（针对本场景）

1. **先做**：给 `tbl_WorkOrderLog` 建 `(WorkOrderID, ModifyTime desc)` 联合索引 → 亿级点查毫秒级 → [[1-索引优化]]
2. **再做**：归档 1 年前日志（或分区切换）→ 在线表体量骤减 → [[4-归档与冷热分离]]
3. 可选：SQL Server Enterprise 版按时间分区 → [[3-表分区]]
4. 暂缓：读写分离 → [[5-读写分离]]
5. 不考虑：分库分表（除非写成为瓶颈）→ [[6-分库分表]]

## 跨数据库通用性

方法论通用，但"功能是否收费 / 实现"因库而异：

- **表分区**：MySQL / PostgreSQL 免费内置；**SQL Server / Oracle 收费**（需 Enterprise 版 / 独立 License）
- **索引 / SQL 优化**：所有主流关系型数据库内置
- **分库分表中间件**：Java 生态成熟（ShardingSphere / MyCat）；**.NET 几乎没有** → 成本高
