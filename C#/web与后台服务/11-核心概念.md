# 11 核心概念（IHostedService / BackgroundService）

> **系列**：web与后台服务 专题（HostedService 专属）｜ **下一篇**：[[12-生命周期与优雅关闭]]

### 背景

> .NET 应用有两类"活"：跟着请求走的（Web 请求处理）和一直跑的（后台任务）。HostedService 就是后者——由 Host 托管、跟应用同生共死的常驻后台服务。
>
> 本篇讲清它的核心概念：它是什么、`IHostedService` 接口、`BackgroundService` 基类、内部机制、注册与 DI、以及怎么选型。

### 1. 什么是 HostedService

回顾 ASP.NET Core 的处理模型：**逻辑跟着请求走**——请求进来 → 处理 → 返回响应 → 结束。一个请求的生命周期很短。

但有些活必须**一直跑、到点跑**，跟请求无关：


| 场景      | 例子                               |
| ----------- | ------------------------------------ |
| 定时任务  | 每天 7:00 生成日报、每天备份数据库 |
| 消息消费  | 从队列里持续取消息处理             |
| 后台清理  | 定期清理临时文件、过期缓存         |
| 心跳/监控 | 持续上报状态、监听崩溃             |

这类"常驻后台"的活，就是 **HostedService** 的用武之地。

`IHostedService` 是 .NET 提供的"**后台服务**"抽象：

- 由 **Host（主机）** 托管：应用启动时自动启动它，应用关闭时自动停止它
- 不是 Web 专属：**Worker Service**（纯后台项目，如你的日报）和 **ASP.NET Core Web** 都支持
- 一句话：**跟应用同生共死的后台任务**

```csharp
// 注册到 Host，应用跑它就跑，应用停它就停
builder.Services.AddHostedService<ScheduleRunner>();
```

### 2. `IHostedService` 接口

```csharp
namespace Microsoft.Extensions.Hosting {
    public interface IHostedService {
        Task StartAsync(CancellationToken cancellationToken);
        Task StopAsync(CancellationToken cancellationToken);
    }
}
```


| 方法         | 调用时机       | 干什么             |
| -------------- | ---------------- | -------------------- |
| `StartAsync` | 应用**启动**时 | 开始后台工作       |
| `StopAsync`  | 应用**关闭**时 | 优雅停止、清理资源 |

对比刚学过的 `IDisposable`（见 [[05-C#内存与GC]] 第 5 节）：`Dispose` 管"非托管资源"，`IHostedService` 管"生命周期"——两者分工不同，但经常配合。

### 3. Start / Stop 钩子的关键特性

`StartAsync` / `StopAsync` 是**生命周期钩子**，不是循环。它们的特性：

1. **只调用一次**：应用启动时调一次 `StartAsync`，关闭时调一次 `StopAsync`，执行完就返回
2. **`StartAsync` 是"点火"**：职责是启动后台工作（`BackgroundService` 里就是启动 `ExecuteAsync`），点火后立即返回，**不阻塞应用启动**
3. **`StopAsync` 是"熄火"**：职责是发出关闭信号（`Cancel` token），然后等后台工作退出
4. **"持续检测关闭"不是钩子的职责**：检测关闭靠 `ExecuteAsync` 循环里每轮的 `while` 条件或 `Task.Delay` 传 token，`StartAsync` 本身不循环
5. **钩子里挂回调，回调执行一次**：像 `CrashMonitorService` 在 `StartAsync` 里 `Register` 回调，`StartAsync` 返回后回调**潜伏**，事件触发时执行一次就结束

一句话：**钩子负责"开始"和"结束"，循环（或回调）负责"持续"或"等待"**。

### 4. `BackgroundService`：帮你写循环的基类

直接实现 `IHostedService` 要自己管循环、管取消，麻烦。所以 .NET 提供了 `BackgroundService` 抽象基类，**你只需重写 `ExecuteAsync`**：

```csharp
// 日报项目的统一调度器
public class ScheduleRunner : BackgroundService {
    protected override async Task ExecuteAsync(CancellationToken stoppingToken) {
        while (!stoppingToken.IsCancellationRequested) {
            await Task.Delay(delay, stoppingToken);
            // ... 到点执行任务
        }
    }
}
```

`stoppingToken` 是"关闭信号"——应用要关闭时它会变成"已取消"，`while` 条件为 false，循环退出，任务优雅结束。

### 5. 内部机制：BackgroundService 源码逐行解读

这是 .NET 官方完整实现（已精简注释）：

```csharp
public abstract class BackgroundService : IHostedService, IDisposable
{
    private Task? _executeTask;                        // 你的循环 Task
    private CancellationTokenSource? _stoppingCts;     // 内部"停止开关"

    protected abstract Task ExecuteAsync(CancellationToken stoppingToken);

    public virtual Task StartAsync(CancellationToken cancellationToken)
    {
        // ① 把宿主的外部 token 和内部停止开关合并成一个 token
        _stoppingCts = CancellationTokenSource.CreateLinkedTokenSource(cancellationToken);
        // ② 立即启动你的循环，拿到 Task
        _executeTask = ExecuteAsync(_stoppingCts.Token);
        // ③ 循环"同步就完成"（如条件立刻 false）→ 返回它让宿主感知；
        //    否则返回 CompletedTask，不阻塞应用启动
        if (_executeTask.IsCompleted)
            return _executeTask;
        return Task.CompletedTask;
    }

    public virtual async Task StopAsync(CancellationToken cancellationToken)
    {
        if (_executeTask == null) return;
        try
        {
            // ④ 触发停止开关 → 你的 stoppingToken 变成"已取消"
            _stoppingCts!.Cancel();
        }
        finally
        {
            // ⑤ 等循环退出；用"永不完成的 Delay"兜底，防止无限等
            await Task.WhenAny(_executeTask,
                Task.Delay(Timeout.Infinite, cancellationToken)).ConfigureAwait(false);
        }
    }

    public virtual void Dispose()
    {
        _stoppingCts?.Cancel();
    }
}
```

#### CreateLinkedTokenSource：把多个取消开关并成一个

```csharp
_stoppingCts = CancellationTokenSource.CreateLinkedTokenSource(cancellationToken);
```

- 作用：把**多个 token 合并成一个**，任何一个源 token 取消，合并出的 token 也跟着取消
- 这里合并两个信号：宿主的 `cancellationToken`（应用要关闭）+ 内部 `_stoppingCts` 自己（`StopAsync` 里 Cancel 它）
- 效果：**无论宿主关你，还是自己主动停，你的 `stoppingToken` 都会变成"已取消"**

#### 为什么 StartAsync 要判断 `IsCompleted`

```csharp
if (_executeTask.IsCompleted)
    return _executeTask;
return Task.CompletedTask;
```

- 如果 `ExecuteAsync` **同步就抛异常**（`IsCompleted` 且 Faulted），返回这个 Task，宿主 await 时能**感知异常**
- 如果返回 `CompletedTask`（循环异步跑），异常发生在后台 Task 里，宿主感知不到——这是"fire-and-forget 的坑"（见 [[05-异常处理]]）
- 所以这一行是为了：**同步错误能及时上报，异步循环不阻塞启动**

#### StopAsync 的 `Task.WhenAny` 妙处

```csharp
await Task.WhenAny(_executeTask, Task.Delay(Timeout.Infinite, cancellationToken));
```

- 为什么不直接 `await _executeTask`？因为如果循环不响应取消，会**无限等**下去
- `Task.Delay(Timeout.Infinite, cancellationToken)` 是个"永不完成的哨兵"：只有外部 `cancellationToken` 取消时它才结束
- 于是 `WhenAny` 变成二选一：**循环退出** 或 **宿主等不及强杀**，谁先完成算谁

#### 不响应 stoppingToken 的后果

```csharp
// ❌ 错误：死循环不检查 token
protected override Task ExecuteAsync(CancellationToken stoppingToken) {
    while (true) { DoWork(); }
}
```

- `StopAsync` 会一直等这个循环，永远等不到
- 宿主有 `ShutdownTimeout`（默认 30 秒），超时直接**强杀进程**
- 日报项目踩过坑 1053"服务没有及时响应启动或控制请求"——就是这类问题
- 所以：**循环里必须响应 `stoppingToken`**（检查 `IsCancellationRequested`，或把它传给 `Task.Delay` / 数据库查询等）

#### ExecuteAsync 提前结束，服务不会自动重启

```csharp
// ⚠️ 只跑一次就退出，服务"完成"后不会重跑
protected override Task ExecuteAsync(CancellationToken stoppingToken) {
    DoWorkOnce();
    return Task.CompletedTask;   // 循环结束 = 服务结束
}
```

- `BackgroundService` **不会自动重启** `ExecuteAsync`——它跑完就完了
- 所以长期运行的服务要用 `while (!stoppingToken.IsCancellationRequested)` 死循环
- 日报的 `ScheduleRunner` 就是用 `while (!ct.IsCancellationRequested)` 包住整个调度逻辑

#### 为什么用 Task.Delay 而不是 Thread.Sleep

```csharp
// ❌ 阻塞线程池线程：整个等待期间占着一个线程
Thread.Sleep(1000);

// ✅ 异步等待：不占线程，1 秒后线程池再调度回来
await Task.Delay(1000, stoppingToken);
```

- `Thread.Sleep` 阻塞当前线程——后台服务是常驻的，浪费会被无限放大
- `Task.Delay` 异步等待，线程被释放去做别的
- 而且 `Task.Delay` 能传 `stoppingToken` 立即响应关闭，`Thread.Sleep` 不能

**对比 Java**：

Java 传统上没有 C# `await Task.Delay` 这种 await 式异步等待，但有几种等价方案：


| C#                     | Java 传统（≤20）                                                         | Java 21+ 虚拟线程                |
| ------------------------ | --------------------------------------------------------------------------- | ---------------------------------- |
| `Thread.Sleep`（阻塞） | `Thread.sleep`（阻塞）                                                    | `Thread.sleep`（不阻塞底层线程） |
| `await Task.Delay`     | `ScheduledExecutorService.schedule` / `CompletableFuture.delayedExecutor` | 直接`Thread.sleep` 即可          |

```java
// 传统方案：延时执行，不阻塞调用线程
ScheduledExecutorService s = Executors.newScheduledThreadPool(1);
s.schedule(() -> doWork(), 1, TimeUnit.SECONDS);

// Java 21 虚拟线程：Thread.sleep 让出载体线程，不再阻塞 OS 线程
Thread.ofVirtual().start(() -> {
    Thread.sleep(1000);   // ✅ 等价于 C# 的 await Task.Delay
    doWork();
});
```

一句话：Java 传统靠 `ScheduledExecutorService.schedule` / `CompletableFuture.delayedExecutor` 实现"延时不阻塞"；**Java 21 虚拟线程出来后，`Thread.sleep` 本身就不再阻塞底层线程**，等价于 C# 的 `await Task.Delay`。

#### BackgroundService 为什么还实现 IDisposable

```csharp
public abstract class BackgroundService : IHostedService, IDisposable
```

- `Dispose` 里只 `_stoppingCts?.Cancel()`——发取消信号，**不等待循环结束**（`Dispose` 是同步方法，不能 await）
- 何时调用：应用关闭、DI 容器释放 Singleton 时
- 呼应（见 [[05-C#内存与GC]] 第 5 节）：`Dispose` 管资源释放，`StopAsync` 管优雅停止，两者分工

#### Task.CompletedTask 是共享单例

```csharp
return Task.CompletedTask;
```

- `Task.CompletedTask` 是一个**全局共享的已完成 Task 单例**，不是每次 new
- 返回它 = 零分配，避免为每个 HostedService 都 new 一个 Task
- 同类：`Task.FromResult(0)` 对小整数也有缓存

### 6. 注册与依赖注入

`AddHostedService<T>()` 内部就是 `AddSingleton`：

```csharp
=> services.AddSingleton<IHostedService, THostedService>();
```

所以 HostedService 是 **Singleton**（进程级唯一实例）。为什么必须 Singleton？宿主要持有一个实例，在启动/关闭时调它的 `StartAsync`/`StopAsync`，全程必须是同一个对象。

但业务层（如 `DbContext`）是 Scoped——Singleton 不能直接注入 Scoped（见 [[01-DI与依赖注入]] 第 8 节）。所以 Worker 里要用 Scoped 服务，必须手动开 Scope：

```csharp
public class MyWorker : BackgroundService {
    private readonly IServiceProvider _sp;   // 注入根容器

    protected override async Task ExecuteAsync(CancellationToken ct) {
        using var scope = _sp.CreateScope();                    // ① 开工作单元
        var orchestrator = scope.ServiceProvider
            .GetRequiredService<OrchestratorService>();          // ② 解析 Scoped
        await orchestrator.GenerateReportAsync(...);
        // ③ using 结束 → scope.Dispose → DbContext 跟着释放
    }
}
```

**项目实景（DailyReportTask）**：

```csharp
public async Task ExecuteAsync(IServiceProvider sp, CancellationToken ct) {
    // ① Singleton 从根容器解析（无状态，安全；catch 块也要用，提到 scope 外）
    var config = sp.GetRequiredService<IOptionsMonitor<CustomReadConfig>>();
    var emailService = sp.GetRequiredService<EmailService>();

    // ② Scoped 必须从 Scope 解析
    using var scope = sp.CreateScope();
    var orchestrator = scope.ServiceProvider.GetRequiredService<OrchestratorService>();
    await orchestrator.GenerateReportAsync(...);
}
```

重试时每次新建 scope（避免复用脏 DbContext）：

```csharp
for (int attempt = 0; attempt < maxRetries; attempt++) {
    using var scope = sp.CreateScope();
    var orchestrator = scope.ServiceProvider.GetRequiredService<OrchestratorService>();
    return await orchestrator.GetAttendanceAsync();
}
```

### 7. 怎么选：直接实现接口 vs 继承基类


| 场景                                  | 选择                          | 理由                       |
| --------------------------------------- | ------------------------------- | ---------------------------- |
| 跑一个循环（定时/轮询/消费）          | **继承 `BackgroundService`**  | 基类帮你管好循环和取消     |
| 只挂生命周期钩子（监听启动/停止事件） | **直接实现 `IHostedService`** | 不需要循环，两个方法自己写 |

**项目实景（日报项目两种都用了）：**

```csharp
// ① 要跑循环 → 继承 BackgroundService
public class ScheduleRunner : BackgroundService { ... }

// ② 只监听"应用停止"事件发告警，不循环 → 直接实现接口
public class CrashMonitorService : IHostedService {
    public Task StartAsync(CancellationToken ct) {
        _lifetime.ApplicationStopped.Register(() => { ...发告警... });
        return Task.CompletedTask;
    }
    public Task StopAsync(CancellationToken ct) => Task.CompletedTask;
}
```

### 8. 小结


| 概念                       | 一句话                                       |
| ---------------------------- | ---------------------------------------------- |
| `IHostedService`           | 跟应用同生共死的后台服务抽象                 |
| `StartAsync` / `StopAsync` | 启动钩子 / 停止钩子                          |
| `BackgroundService`        | 帮你管循环和取消的基类，只需写`ExecuteAsync` |
| `stoppingToken`            | 关闭信号，响应它才能优雅退出                 |
