# 12 生命周期与优雅关闭

> **系列**：web与后台服务 专题（HostedService 专属）｜ **上一篇**：[[11-核心概念]] ｜ **下一篇**：[[13-定时调度实战]]

### 背景

> 后台服务（HostedService）的生命周期完全由 Host（主机）管理：应用启动时按注册顺序依次 `StartAsync`，关闭时逆序 `StopAsync`。理解这套生命周期，才能写出"优雅关闭"的后台任务。
>
> 本篇讲完整生命周期、启动/停止顺序、`CancellationToken` 传播链、`ShutdownTimeout` 超时、`IHostApplicationLifetime` 三事件。

### 1. 完整生命周期（一张图）

```
应用启动
   ↓
host.Build() 构建完成
   ↓
host.StartAsync()
   ↓ 按注册顺序依次调用每个 IHostedService.StartAsync()
   ↓
┌─────────────────────────────┐
│  应用正常运行，后台服务在跑    │
└─────────────────────────────┘
   ↓
关闭信号（Ctrl+C / sc stop / SIGTERM）
   ↓
host.StopAsync()
   ↓ 按注册逆序依次调用每个 IHostedService.StopAsync()
   ↓
进程退出
```

关键：后台服务的"生"由 `StartAsync` 决定，"死"由 `StopAsync` 决定，全程由 Host 托管，你不需要手动管理。

### 2. 启动顺序：按注册顺序依次 Start

```csharp
builder.Services.AddHostedService<CrashMonitorService>();  // 第 1 个注册
builder.Services.AddHostedService<ScheduleRunner>();       // 第 2 个注册
```

- `StartAsync` 按**注册顺序**依次调用：先 `CrashMonitorService`，再 `ScheduleRunner`
- 是**串行**的：前一个 `StartAsync` 完成，才轮到下一个
- 所以 `StartAsync` 里别做太重的同步工作，否则拖慢整个应用启动

### 3. 停止顺序：逆序 Stop

- `StopAsync` 按注册的**逆序**调用：先 `ScheduleRunner`，再 `CrashMonitorService`
- 目的：**先停"上层依赖"，再停"底层服务"**（像栈，后进先出）
- 保证被依赖的服务停止前，依赖它的服务已经停完

### 4. CancellationToken 传播链

关闭信号从操作系统一路传到你的 `stoppingToken`：

```
操作系统信号（Ctrl+C / sc stop / SIGTERM / kill）
   ↓
Host 收到，触发 ApplicationStopping
   ↓
调用每个服务的 StopAsync(外部 token)
   ↓
BackgroundService.StopAsync：_stoppingCts.Cancel()
   ↓
ExecuteAsync 里的 stoppingToken 变成"已取消"
   ↓
你的 while 循环退出 / Task.Delay 抛 OperationCanceledException
```

**关键理解**：`stoppingToken` 不是凭空来的，它是这条链的末端。你响应它，就是响应"应用要关闭了"这件事。

### 5. ShutdownTimeout：优雅关闭的倒计时

- 宿主给**所有** `StopAsync` 总共的宽限时间，默认 **30 秒**
- 超时 → 宿主不再等，直接**强杀进程**（未完成的清理全部中断）

```csharp
// 调整宽限时间
builder.Services.Configure<HostOptions>(options => {
    options.ShutdownTimeout = TimeSpan.FromSeconds(10);  // 改 10 秒
});
```

- 如果你的 `StopAsync` 清理耗时超过 30 秒（比如要等一个长任务结束），就要调大
- 反之，如果 `ExecuteAsync` 不响应 `stoppingToken`（见 [[11-核心概念]]），30 秒一到就被强杀
- **日报项目踩坑 1053"服务没有及时响应启动或控制请求"** 就是这类关闭超时问题的表现

### 6. IHostApplicationLifetime 三事件

```csharp
public interface IHostApplicationLifetime {
    CancellationToken ApplicationStarted { get; }   // 启动完成
    CancellationToken ApplicationStopping { get; }  // 开始关闭
    CancellationToken ApplicationStopped { get; }   // 关闭完成
    void StopApplication();                          // 主动请求关闭
}
```

用法：在 `StartAsync` 里给事件注册回调：

```csharp
// 日报项目 CrashMonitorService：监听"关闭完成"，异常退出时发告警
public Task StartAsync(CancellationToken ct) {
    _lifetime.ApplicationStopped.Register(() => {
        if (Environment.ExitCode != 0) {   // 退出码非 0 = 异常退出
            SendCrashAlert();              // 发告警邮件
        }
    });
    return Task.CompletedTask;
}
```

三个事件时机：

| 事件 | 时机 | 典型用途 |
|---|---|---|
| `ApplicationStarted` | 启动完成后 | 打印"服务已就绪"、上报状态 |
| `ApplicationStopping` | 开始关闭时 | 主动停止内部工作 |
| `ApplicationStopped` | 关闭完成后 | 收尾、告警、记录退出码 |

### 7. 小结

| 概念 | 一句话 |
|---|---|
| 启动顺序 | 按注册顺序串行 `StartAsync` |
| 停止顺序 | 按注册逆序串行 `StopAsync` |
| `stoppingToken` | 关闭信号的末端，响应它 = 优雅退出 |
| `ShutdownTimeout` | 默认 30 秒宽限，超时强杀 |
| `IHostApplicationLifetime` | 三事件 + 主动关闭
