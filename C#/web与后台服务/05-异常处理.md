# 05 异常处理

> **系列**：web与后台服务 专题（通用）｜ **上一篇**：[[04-并发]]

### 背景

> 异常处理是任何应用都绕不开的。本篇讲**通用异常处理与可靠性**：最佳实践、重试、熔断降级、健康检查、看门狗、监控告警——Web 和后台服务通用。（崩溃监控的 .NET 专属部分见 [[14-异常与崩溃监控]]）

### 1. 异常处理最佳实践

- **别裸 catch 吞掉一切**：`catch (Exception ex) { }` 至少记录日志，否则问题永远发现不了
- **用异常过滤器区分"可重试"vs"致命"**：

```csharp
catch (IOException ex) when (attempt < 3)   // 可重试：文件被占用
catch (Exception ex)                         // 致命：其他都算
```

- **别用异常控制正常流程**：异常有栈展开开销，正常流程用返回值 / Result 模式

### 2. 幂等重试

> 重试的前提是**任务重复执行无副作用**（幂等）。

- 场景：发邮件重试会**重复发**；扣库存重试会**重复扣**
- 解法：任务带**幂等键**（Idempotency Key）、**去重表**、或"先查后写"
- 判断：读操作重试安全（如查数据），写操作重试要格外小心

### 3. 重试策略：指数退避、抖动、Polly

**指数退避（Exponential Backoff）**：失败后等待 1s → 2s → 4s → 8s……避免立刻打爆依赖。

**抖动（Jitter）**：在退避时间上**加随机量**，避免多个任务同时失败后同时重试（重试风暴）。

**Polly 库**（.NET 标准重试库）：

```csharp
Policy.Handle<IOException>()
    .WaitAndRetryAsync(new[] {
        TimeSpan.FromSeconds(1),
        TimeSpan.FromSeconds(2),
        TimeSpan.FromSeconds(4),
    });   // 1s → 2s → 4s 退避重试
```

### 4. 熔断与降级

> 重试解决"临时抖动"，**熔断**解决"对方已经挂了"。

- **熔断（Circuit Breaker）**：连续失败 N 次 → 熔断器打开，**直接失败不再打对方** → 冷却后半开试探
- **降级（Fallback）**：失败时返回**兜底值/缓存**，而不是抛错
- Polly：

```csharp
Policy.Handle<Exception>()
    .CircuitBreakerAsync(5, TimeSpan.FromMinutes(1));   // 连续 5 次失败熔断 1 分钟
```

### 5. 健康检查

> 让外部知道"我还活着"。

- ASP.NET Core Health Checks：`AddHealthChecks()` + `/health` 端点
- K8s / 监控系统用**探针**（Probe）定期探活
- 后台服务也可用 `BackgroundService` 定期**心跳上报**（写时间戳，监控比对）

### 6. 看门狗（Watchdog）

> 服务"**卡死**"（死锁、无限循环）不抛异常，异常机制发现不了——看门狗治这个。

- **看门狗**：独立线程定期检查"上次心跳时间"，超时判定卡死 → 强制重启
- 思想：异常是"能感知的挂"，卡死是"**感知不到的挂**"
- Web 里 K8s 的 `liveness probe` 就是容器级看门狗，本质同源

```csharp
// 伪代码：看门狗线程
while (!ct.IsCancellationRequested) {
    if (DateTime.UtcNow - lastHeartbeat > TimeSpan.FromMinutes(5)) {
        KillAndRestart();   // 5 分钟没心跳 = 卡死，强制重启
    }
    await Task.Delay(TimeSpan.FromMinutes(1), ct);
}
```

### 7. 监控与告警（Metrics / APM）

> 告警是"**事后通知**"，生产上要"**事前指标**"——发现"慢慢变坏"。

- **Metrics**：Prometheus + Grafana，记录成功率、执行时长、失败数
- **APM**：Application Insights / OpenTelemetry，追踪调用链路
- 指标比日志更能发现渐进问题（比如执行时长逐周上升，还没挂但快挂了）

### 8. 小结

| 概念 | 一句话 |
|---|---|
| 最佳实践 | 别裸 catch、用过滤器区分、别用异常控制流程 |
| 幂等 | 重试的前提是重复执行无副作用 |
| 重试 | 指数退避 + 抖动（Polly） |
| 熔断 | 对方挂了就别再打，冷却后试探 |
| 健康检查 | 让外部知道我还活着 |
| 看门狗 | 治"卡死"这种感知不到的挂 |
| 监控 | 事前指标比事后告警更重要 |
