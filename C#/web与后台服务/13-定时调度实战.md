# 13 定时调度实战

> **系列**：web与后台服务 专题（HostedService 专属）｜ **上一篇**：[[12-生命周期与优雅关闭]] ｜ **下一篇**：[[14-异常与崩溃监控]]

## 本模块知识点

1. 自写循环（while + Task.Delay）
2. 通用多任务调度器（ScheduleRunner）
3. 防重复触发、容错窗口、超时控制

---

### 背景

> 后台服务最常见的需求之一就是"到点干某事"：定时报表（每天 7:30 生成日报）、定时备份（凌晨备份数据库）、定时预警（9:30 检查临期工单）、周期巡检（每 14 天检查基板）。
>
> 定时任务分两类：**固定间隔**（每 5 分钟跑一次，`Task.Delay` 就够）和**固定时刻**（每天 7:30 跑，要算"距离下次触发还有多久"）。
>
> 日报项目两类都有：5 个任务、触发时刻各不相同，所以需要一个**通用调度器**统一管理。
>
> 本篇以日报的 `ScheduleRunner` 为教材，逐步拆解一个生产级调度器的所有技巧。

### 1. 最简单的自写循环

一个定时任务最朴素的写法：

```csharp
protected override async Task ExecuteAsync(CancellationToken ct) {
    while (!ct.IsCancellationRequested) {
        await Task.Delay(TimeSpan.FromMinutes(5), ct);   // 每 5 分钟一次
        DoWork();
    }
}
```

- `while` 保证一直转，`Task.Delay(delay, ct)` 保证关闭时立即响应
- 这适合**固定间隔**的任务（每 5 分钟、每 1 小时）

但日报的需求是**每天固定时刻**触发（7:00、7:30、9:30、19:00），固定间隔做不到——所以要算"距离下一次触发还有多久"。

### 2. 多任务调度：接口 + 统一调度器

一个任务好办，一堆任务（日报 5 个定时任务）就需要统一管理。日报项目用**策略接口 + 调度器**：

```csharp
// ① 策略接口：每个定时任务实现它
public interface IScheduledTask {
    TimeSpan[] Schedules { get; }                    // 触发时间点数组
    TimeSpan? Timeout { get; }                       // 超时时间
    Task ExecuteAsync(IServiceProvider sp, CancellationToken ct);  // 执行逻辑
}

// ② 调度器：注入所有 IScheduledTask，统一调度
public class ScheduleRunner : BackgroundService {
    private readonly IEnumerable<IScheduledTask> _tasks;   // 拿到所有任务
    ...
}
```

注册时，每个任务一个 `AddSingleton<IScheduledTask, DailyReportTask>()`，调度器注入 `IEnumerable<IScheduledTask>` 就能拿到全部。

### 3. 计算"距离下一次触发还有多久"

```csharp
// 遍历所有任务的所有时间点，取最近的 delay
var delays = _tasks.SelectMany(t => t.Schedules)
    .Select(ScheduleHelper.CalculateNextDelay)   // 每个时间点 → 距现在的时长
    .ToList();
var delay = delays.Count > 0 ? delays.Min() : TimeSpan.FromHours(1);  // 取最小
```

- `SelectMany` 把所有任务的所有时间点**摊平**成一个列表
- `CalculateNextDelay` 算每个时间点距现在的时长（跨天要 +24h）
- `Min()` 取最近的一个 → 这就是"睡多久"

### 4. 休眠到点 + 容错窗口

```csharp
try { await Task.Delay(delay, ct); }
catch (OperationCanceledException) { break; }   // 关闭 → 退出

// 找出 ±2 分钟内的到期任务（容错窗口）
var now = DateTime.Now.TimeOfDay;
var dueTasks = _tasks
    .SelectMany(t => t.Schedules, (t, s) => (Task: t, Sched: s))
    .Where(x => Math.Abs((now - x.Sched).TotalMinutes) < 2)
    ...
```

**为什么用 ±2 分钟容错窗口，而不是精确匹配秒？**

- `Task.Delay` 睡醒后，实际执行时间有微小误差（线程调度、系统负载）
- 如果要求"当前时刻 == 触发时刻"精确相等，极可能因为差几毫秒而**错过**
- 用 ±2 分钟窗口："睡到 7:29~7:31 之间醒来，都算 7:30 的任务到期"

### 5. 防重复触发：HashSet 去重

```csharp
// 记录当天已触发过的 (任务, 时刻)
var triggeredTimes = new HashSet<(string TaskName, TimeSpan Sched)>();

// Add 返回 false = 该 (任务, 时刻) 今天已触发过 → 跳过
.Where(x => Math.Abs((now - x.Sched).TotalMinutes) < 2
    && triggeredTimes.Add((x.Task.GetType().Name, x.Sched)))
```

**为什么需要防重复？**

- 一个任务执行时间可能很长（日报要 90 分钟）
- 如果任务从 7:30 跑到 9:00，期间调度器又醒了几次，每次都发现"7:30 在 ±2 分钟窗口内"→ 会重复触发
- `HashSet.Add` 返回 `false` 表示已存在，用它天然去重

### 6. 跨天清空

```csharp
if (DateTime.Today != curDate) {   // 日期变了
    curDate = DateTime.Today;
    triggeredTimes.Clear();         // 清空"已触发"记录，新的一天重新计数
}
```

否则昨天触发的记录会一直占着，今天 7:30 的任务永远被当成"已触发"而跳过。

### 7. 并发执行：fire-and-forget

```csharp
foreach (var task in dueTasks) {
    _ = Task.Run(async () => { ... }, ct);   // 不 await，丢弃 Task
}
```

- **不 await**：多个任务并发跑，一个任务卡死（比如邮件发不出）不会阻塞调度循环和其他任务
- `_ =` 显式丢弃 Task（告诉编译器"我故意不等"）

### 8. 超时控制：Linked CTS

```csharp
using var timeoutCts = task.Timeout.HasValue
    ? new CancellationTokenSource(task.Timeout.Value)      // 超时定时器
    : null;
using var linkedCts = task.Timeout.HasValue
    ? CancellationTokenSource.CreateLinkedTokenSource(ct, timeoutCts!.Token)  // 串联
    : CancellationTokenSource.CreateLinkedTokenSource(ct);

await task.ExecuteAsync(_sp, linkedCts.Token);

// 判断超时：linkedCts 取消了，但主 ct 没取消 = 是超时
if (linkedCts.IsCancellationRequested && !ct.IsCancellationRequested) {
    _logger.LogError("任务 {Task} 执行超时（{Timeout}），已强制取消", taskName, task.Timeout);
}
```

- `new CancellationTokenSource(时长)` = 一个"倒计时定时器"，到点自动取消
- `CreateLinkedTokenSource` 把**主 token（关闭）+ 超时 token** 串成一个：任一取消，任务都能感知
- 判断是否超时：合并 token 取消了，但主 token 没取消 → 说明是超时触发

### 9. 异常处理

```csharp
try {
    await task.ExecuteAsync(_sp, linkedCts.Token);
}
catch (OperationCanceledException) { }   // 取消/超时，正常，忽略
catch (Exception ex) {
    _logger.LogError(ex, "任务 {Task} 执行异常", taskName);   // 单个任务挂了不拖垮调度器
}
```

而**主循环**的异常要致命处理：

```csharp
catch (OperationCanceledException) { }   // 正常关闭
catch (Exception ex) {
    _logger.LogCritical(ex, "ScheduleRunner 主循环崩溃");
    Environment.ExitCode = 1;             // 设退出码 → CrashMonitorService 会发告警
    throw;
}
```

### 10. 小结

| 技巧 | 一句话 |
|---|---|
| 自写循环 | `while` + `Task.Delay(delay, ct)` |
| 计算 delay | `SelectMany` 摊平所有时间点，取 `Min` |
| 容错窗口 | ±2 分钟，避免误差导致错过 |
| 防重复触发 | `HashSet.Add` 返回 false 去重 |
| 跨天清空 | `DateTime.Today` 变化就 `Clear` |
| 并发执行 | `Task.Run` + 不 await |
| 超时控制 | 倒计时 CTS + `CreateLinkedTokenSource` |
| 异常分级 | 单任务异常记录即可，主循环异常设退出码 |
