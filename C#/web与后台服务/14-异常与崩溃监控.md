# 14 异常与崩溃监控

> **系列**：web与后台服务 专题（HostedService 专属）｜ **上一篇**：[[13-定时调度实战]] ｜ **下一篇**：[[15-部署]]

### 背景

> 后台服务是 7×24 常驻的，**挂了没人知道是最可怕的**。崩溃监控是后台服务的"保命"工程。
>
> 本篇讲 .NET 后台服务的崩溃监控体系（通用异常处理见 [[05-异常处理]]）。

### 1. 三层防线：异常处理体系

> 思想：后台服务常驻，异常要**分层兜底**——单层挡不住：①业务代码 try-catch（本地处理）→ ②全局未处理异常（AppDomain）→ ③进程退出监控（CrashMonitor 告警）。

```
业务代码 try-catch  ── 能处理的就地处理
        ↓ 没接住的
AppDomain.UnhandledException  ── 记录 + 发告警 + 退出
        ↓ 进程退出
CrashMonitorService  ── 监听退出码，异常退出再补一次告警
```

### 2. 单任务异常：try-catch 记录

> 思想：单个后台任务（日报/预警）挂了，**记录日志继续跑**，不拖垮整个服务。

```csharp
catch (Exception ex) { _logger.LogError(ex, "任务执行异常"); }   // 记录，继续
```

### 3. 主循环异常：设退出码

> 思想：调度器主循环崩溃是"致命伤"，**设退出码 + 抛出**让进程退出，交给崩溃监控。

```csharp
catch (Exception ex) {
    _logger.LogCritical(ex, "主循环崩溃");
    Environment.ExitCode = 1;   // 非 0 退出码 → 触发 CrashMonitor 告警
    throw;
}
```

### 4. 全局未处理异常：AppDomain.UnhandledException

> 思想：主线程/后台线程的**未捕获异常**兜底拦截 → 记录 + 发告警 + 退出。

```csharp
AppDomain.CurrentDomain.UnhandledException += (s, e) => {
    Log.Fatal(e.ExceptionObject as Exception, "未处理异常导致崩溃");
    SendAlert();            // 同步发告警（等发完再退）
    Environment.Exit(1);    // 强制退出
};
```

### 5. Fire-and-forget 异常：UnobservedTaskException

> 思想：`Task.Run` 丢弃的 Task 异常默认"无人认领"，注册 `UnobservedTaskException` 兜底记录（防止进程被拖死）。

```csharp
TaskScheduler.UnobservedTaskException += (s, e) => {
    Log.Error(e.Exception, "未观察到的 Task 异常");
    e.SetObserved();   // 标记已处理，避免进程因未观察异常被终结
};
```

### 6. 崩溃监控：CrashMonitorService

> 思想：进程退出时看**退出码**——0 是正常关闭不告警，非 0 是异常退出发告警。

```csharp
public class CrashMonitorService : IHostedService {
    public Task StartAsync(CancellationToken ct) {
        _lifetime.ApplicationStopped.Register(() => {
            if (Environment.ExitCode != 0) SendCrashAlert();   // 异常退出 → 告警
        });
        return Task.CompletedTask;
    }
}
```

### 7. 小结

| 环节 | 一句话 |
|---|---|
| 单任务异常 | try-catch 记录，不拖垮服务 |
| 主循环异常 | 设退出码 + 抛出 |
| 全局未处理异常 | AppDomain 兜底：记录 + 告警 + 退出 |
| Fire-and-forget | UnobservedTaskException 兜底 |
| 崩溃监控 | CrashMonitor 看退出码发告警 |
