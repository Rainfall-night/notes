## 1. 特性（Attribute）

### 1.1 特性是什么：给代码贴"标签"

特性 = 给代码元素（类/方法/属性/参数/枚举成员）附加的**元数据标签**：

```csharp
[Table("tbl_WorkOrder")]          // 给类贴标签：对应数据库表
public class WorkOrderEntity : Entity { ... }

[ApiController]                   // 给类贴标签：这是 API 控制器
[Route("/api/WorkOrder")]
public class WorkOrderController : ControllerBase { ... }

[HttpGet("GetList")]              // 给方法贴标签：HTTP GET 路由
public async Task<ExecuteResult<...>> GetList(...) { ... }

[Description("进行中")]           // 给枚举成员贴标签：描述文字
Moving = 8,
```

**生态位对照**：C# 特性 = Java 注解（Annotation），两者都是"给代码贴元数据标签"：


| Java（Spring/JPA 生态）          | C#（ASP.NET Core / EF Core） | 作用     |
| ---------------------------------- | ------------------------------ | ---------- |
| `@RequestMapping("/api")`        | `[Route("/api")]`            | 路由     |
| `@Entity` / `@Table(name="...")` | `[Table("...")]`             | 表映射   |
| `@Autowired`                     | （构造函数注入，无需特性）   | 依赖注入 |
| `@Override`                      | `override` **关键字**        | 重写标记 |

> 有意思：重写这件事，Java 用**注解** `@Override`，C# 用**关键字** `override`——同样需求两种设计。

### 1.2 特性的本质

- 特性本质是一个**类**，继承自 `Attribute`
- 用 `[ ]` 语法贴到代码元素上
- ⚠️ **特性本身不产生任何行为**——只是"标记"，要靠**反射**读取才生效

项目里的自定义特性：

```csharp
[AttributeUsage(AttributeTargets.Property)]   // 限定：只能贴在属性上
public class PermissionAttribute : Attribute {
    public string? Description { get; set; }
}
```

### 1.3 项目里用到的内置特性


| 特性                                   | 作用             | 项目例子                     |
| ---------------------------------------- | ------------------ | ------------------------------ |
| `[Table("...")]`                       | 映射数据库表名   | `[Table("tbl_WorkOrder")]`   |
| `[ApiController]`                      | 标记 API 控制器  | Controller 类                |
| `[Route]` / `[HttpGet]` / `[HttpPost]` | 路由             | `[HttpPost("MachineCards")]` |
| `[FromBody]`                           | 从请求体绑定参数 | `[FromBody] List<string>`    |
| `[Required]`                           | 参数校验必填     | `LoginRequest`               |
| `[Description]`                        | 描述文字         | 枚举成员                     |

### 1.4 核心理解：特性自己不做任何事

`[Table("tbl_WorkOrder")]` 这行代码本身不执行任何东西。是 **EF Core 框架**在运行时读取这个特性，才知道映射关系。

```
特性贴标签  +  反射读标签  =  框架行为
   [Table]        EF Core 读它 → 生成正确的表映射
   [HttpGet]      ASP.NET Core 读它 → 注册路由
```

**特性是"死的"，反射让它"活"起来**——下一课（反射）。

### 1.5 对照：Java 注解（Annotation）

**定义对比**：

```java
// Java 注解：@interface + "方法形式"的成员
@Retention(RetentionPolicy.RUNTIME)   // 保留到运行时（反射才能读到）
@Target(ElementType.TYPE)             // 只能贴在类上
public @interface MyAnnotation {
    String value() default "";        // 成员：长得像方法，默认值用 default
    int level() default 1;
}

@MyAnnotation(value = "hello", level = 3)
public class MyClass { ... }
```

```csharp
// C# 特性：class : Attribute + "属性形式"的成员
[AttributeUsage(AttributeTargets.Class)]   // 对应 @Target
public class MyAttribute : Attribute {
    public string Value { get; set; } = "";   // C# 用属性
    public int Level { get; set; } = 1;
}

[MyAttribute(Value = "hello", Level = 3)]   // 对应 @MyAnnotation
public class MyClass { ... }
```


| 维度       | Java 注解                           | C# 特性                              |
| ------------ | ------------------------------------- | -------------------------------------- |
| 定义关键字 | `@interface`                        | `class : Attribute`                  |
| 成员形式   | 方法形式`String value() default ""` | 属性形式`string Value { get; set; }` |
| 元信息     | `@Retention` / `@Target`            | `[AttributeUsage]`                   |
| 保留策略   | SOURCE / CLASS / RUNTIME            | 运行时默认全保留                     |

**使用有两条路径（不全是反射）**：


|                   | Java                               | C#                                         |
| ------------------- | ------------------------------------ | -------------------------------------------- |
| ① 运行时反射读取 | `MyClass.class.getAnnotation(...)` | `typeof(MyClass).GetCustomAttributes(...)` |
| ② 编译期生成代码 | 注解处理器（Lombok`@Getter`）      | Source Generator                           |

像 Lombok 的 `@Getter`，注解运行时毫无痕迹，代码是**编译期生成**进去的，完全不走反射。

**一句话总结**：Java 注解 ≈ C# 特性（生态位一致）；`@interface` ≈ `class : Attribute`；注解处理器 ≈ Source Generator。

## 2. 反射（Reflection）

### 2.1 反射是什么

反射 = **运行时检查类型结构的能力**——运行时去"看"类的属性、方法、特性长什么样。正常代码编译期就知道类型，反射是**运行时才查**。

### 2.2 项目里的三处真实用例

**① ExcelService：反射遍历 DTO 属性，按列名取值**

```csharp
var props = typeof(WorkOrderDTO).GetProperties();
var columnProps = columns.Select(col => props.FirstOrDefault(p => p.Name == col.Value)).ToList();
var val = columnProps[c]?.GetValue(item);   // 运行时读属性值
```

为什么必须反射：导出列是前端动态传的，后端不知道要导哪些列，只能运行时按名字找属性。

**② AuthService：反射找带 [Permission] 的属性**

```csharp
typeof(Permission)
    .GetProperties()
    .Where(p => p.IsDefined(typeof(PermissionAttribute), false))  // 只留贴了 [Permission] 的
    .Select(p => p.Name)
```

**③ EnumHelper：反射读枚举的 [Description]**

```csharp
FieldInfo field = typeof(T).GetField(Enum.GetName(typeof(T), enumValue));
var descAttrs = field.GetCustomAttributes(typeof(DescriptionAttribute), false);
return ((DescriptionAttribute)descAttrs[0]).Description;
```

### 2.3 特性 + 反射的配合

```
[Description("进行中")]          ← 特性：贴标签（死的）
field.GetCustomAttributes(...)   ← 反射：读标签（让它活起来）
```

特性是死的，反射是让它活起来的那只手。`EnumHelper` 就是最典型的"反射读特性"。

### 2.4 反射的代价

- 反射慢（运行时查找，比直接调用慢几十上百倍）
- 框架（EF Core / ASP.NET Core）用反射做"启动时一次性映射"，不在热路径反复反射
- 项目里 ExcelService 导出反射一次可接受；EnumHelper 每次转描述都反射，但枚举成员少，可接受

### 2.5 反射常用方法速查


| API                                           | 作用                          |
| ----------------------------------------------- | ------------------------------- |
| `typeof(T)` / `obj.GetType()`                 | 拿类型的 Type 对象            |
| `type.GetProperties()`                        | 拿所有属性 →`PropertyInfo[]` |
| `type.GetFields()`                            | 拿所有字段                    |
| `type.GetMethods()`                           | 拿所有方法                    |
| `type.GetProperty(name)` / `GetField(name)`   | 按名拿属性/字段               |
| `prop.GetValue(obj)`                          | 读属性值（反射调用）          |
| `prop.SetValue(obj, value)`                   | 写属性值                      |
| `type.GetCustomAttributes(typeof(A), false)`  | 拿类上的特性                  |
| `field.GetCustomAttributes(typeof(A), false)` | 拿字段/枚举成员上的特性       |
| `prop.IsDefined(typeof(A), false)`            | 判断是否贴了某特性            |
| `Enum.GetName(typeof(T), value)`              | 枚举值 → 名字                |
| `Activator.CreateInstance(type)`              | 动态创建实例                  |
| `method.Invoke(obj, args)`                    | 反射调用方法                  |

记忆：反射的 API 都是 `Get...`（获取信息）。

## 3. 表达式树（Expression Tree）

### 3.1 表达式树是什么

把一段 Lambda 用**对象树**表示出来，可以检查、修改、执行、翻译。

### 3.2 核心区别：委托 vs 表达式树

```csharp
// 委托：编译好的"可执行代码"，直接能跑
Func<int, bool> isEven = x => x % 2 == 0;
bool r = isEven(4);        // 直接执行

// 表达式树：代码的"结构描述"，能读、能改、能翻译
Expression<Func<int, bool>> expr = x => x % 2 == 0;
```

一句话：`Func<...>` = 编译好的方法；`Expression<Func<...>>` = 方法的"解剖图"。

### 3.3 两大用途

**① 翻译成别的语言（EF Core 核心机制）**

```csharp
db.WorkOrders.Where(w => w.State == 8)
// EF Core 拿到 Expression，翻译成 SQL：WHERE State = 8
```

**② 动态生成代码并执行（CompileGetter）**

```csharp
var obj = Expression.Parameter(typeof(WorkOrderDTO), "x");       // 参数 x
var prop = Expression.Property(obj, propertyInfo);               // x.属性
var body = Expression.Convert(prop, typeof(object));             // (object)x.属性
var lambda = Expression.Lambda<Func<WorkOrderDTO, object?>>(body, obj);  // x => (object)x.属性
var getter = lambda.Compile();   // 编译成委托
```

### 3.4 表达式树是一棵树

```
Lambda (x => ...)
   |
Convert (object)
   |
Property (x.当前数量)
   |
Parameter (x)
```

每个 `Expression.XXX` 造一个节点，节点连起来就是树。

### 3.5 表达式树 vs 反射


|      | 反射               | 表达式树                     |
| ------ | -------------------- | ------------------------------ |
| 方式 | 运行时"查"类型信息 | 运行时"构建"代码             |
| 执行 | GetValue 每次都慢  | Compile 一次后是普通委托，快 |
| 用途 | 查属性/特性        | 翻译成 SQL / 动态生成委托    |

### 3.6 表达式树常用方法速查


| API                                  | 作用        | 等价代码    |
| -------------------------------------- | ------------- | ------------- |
| `Expression.Parameter(type, name)`   | 参数节点    | `x`         |
| `Expression.Property(obj, prop)`     | 属性访问    | `x.属性`    |
| `Expression.Constant(value)`         | 常量节点    | `2`         |
| `Expression.Convert(expr, type)`     | 类型转换    | `(object)x` |
| `Expression.Add(l, r)`               | 加法        | `a + b`     |
| `Expression.Equal(l, r)`             | 相等比较    | `a == b`    |
| `Expression.AndAlso(l, r)`           | 逻辑与      | `a && b`    |
| `Expression.Call(obj, method, args)` | 方法调用    | `obj.M()`   |
| `Expression.Lambda<T>(body, params)` | 组装 Lambda | `x => ...`  |
| `lambda.Compile()`                   | 编译成委托  | 得到 Func   |

记忆：表达式树 API 都是 `Expression.Xxx`（造节点）。

## 4. 扩展方法（Extension Method）

### 4.1 什么是扩展方法

给**已有类型**添加新方法，不改原类、不用继承。项目真实例子（`Common/ExecuteResult.cs`）：

```csharp
public static class ExecuteResultHelper {                    // ① static 类
    public static ExecuteResult<TSource> AddExtendData<TSource>(
        this ExecuteResult<TSource> source,                  // ② 第一个参数前加 this
        string key, string value) { ... }
}

result.AddExtendData("CurrentCountSum", sum);   // 像 ExecuteResult<T> 自己的方法
```

### 4.2 定义语法三要素

| 要素 | 说明 |
|------|------|
| static 类 | 扩展方法必须放在静态类里 |
| static 方法 | 方法本身也是静态的 |
| `this` 参数 | 第一个参数前加 this，指定"扩展哪个类型" |

### 4.3 LINQ 的本质就是扩展方法

`.Where().Select().ToList()` 都不是 `List<T>` 自己定义的方法，而是 `System.Linq.Enumerable` 静态类的扩展方法：

```csharp
public static class Enumerable {
    public static IEnumerable<T> Where<T>(this IEnumerable<T> source, Func<T, bool> predicate) { ... }
}
```

`list.Where(...)` 其实是 `Enumerable.Where(list, ...)` 的语法糖。

### 4.4 原理：编译器翻译

```csharp
result.AddExtendData("key", "value");
// 编译器翻译成 ↓ 普通静态调用
ExecuteResultHelper.AddExtendData(result, "key", "value");
```

扩展方法没有魔法，就是语法糖，编译后是普通静态方法调用。

### 4.5 为什么 List<T> 能调 Where

`Where` 扩展的是 `IEnumerable<T>`，`List<T>` 实现了 `IEnumerable<T>`，所以能用所有 LINQ 扩展方法。

### 4.6 this 参数：被扩展对象本身（入参）

`this` 参数**不是"返回值"**，而是**被扩展的对象本身，作为第一个入参传进来**：

```csharp
public static ExecuteResult<TSource> AddExtendData<TSource>(
    this ExecuteResult<TSource> source,   // ← source = 调用方 result 本身（入参）
    string key, string value)
{
    if (source.ExtendData is null) {              // ① 读对象的属性
        source.ExtendData = new Dictionary<string, string>();   // ② 改对象的属性
    }
    source.ExtendData.Add(key, value);            // ③ 增强操作
    return source;                                // ④ 返回原对象（链式调用）
}
```

**方法内部套路**：

```
1. 拿到 this 对象（入参）
2. 读它 / 改它 / 对它做任何处理
3. return 结果（可返回原对象实现链式，也可返回新值）
```

返回**新值**（不返回原对象）的例子：

```csharp
public static int WordCount(this string str) {   // this string = 被扩展的字符串
    if (string.IsNullOrEmpty(str)) return 0;
    return str.Split(' ').Length;    // 返回 int，跟原类型无关
}
int n = "hello world".WordCount();   // 2
```

## 5. yield 迭代器

### 5.1 yield return：逐个返回，而不是一次性全给

```csharp
// 普通方法：一次性生成整个 List，全部塞进内存
List<int> GetEven(List<int> nums) {
    var result = new List<int>();
    foreach (var n in nums) {
        if (n % 2 == 0) result.Add(n);
    }
    return result;
}

// yield 版：逐个返回，用到哪个才生成哪个
IEnumerable<int> GetEven2(List<int> nums) {
    foreach (var n in nums) {
        if (n % 2 == 0) yield return n;   // 每次"吐"一个，然后暂停
    }
}
```

### 5.2 核心：惰性（lazy）——边生成边消费

| | 普通 List 返回 | yield return |
|---|---|---|
| 生成时机 | 调用方法就全算出来 | 迭代到哪才生成到哪 |
| 内存 | 一次性占整个集合 | 只占当前一个元素 |
| 提前停止 | 后面的白算了 | 后面的不生成 |

### 5.3 最直观的例子：无限序列

```csharp
IEnumerable<int> Infinite() {
    int i = 0;
    while (true) yield return i++;   // 无限序列，但不会立刻死循环
}
foreach (var n in Infinite().Take(3)) {
    Console.WriteLine(n);   // 0 1 2
}
```

无限序列没法用 List 表达，但 yield 可以。

### 5.4 原理：编译器生成"状态机"

yield return 方法编译后变成状态机（实现 IEnumerator），每次迭代恢复上次暂停位置继续执行。

### 5.5 yield break：提前结束迭代

```csharp
IEnumerable<int> GetPositive(int[] nums) {
    foreach (var n in nums) {
        if (n < 0) yield break;   // 遇负数，整个迭代直接结束
        yield return n;
    }
}
```

### 5.6 和 LINQ 延迟执行的关系

LINQ 的 Where/Select 延迟执行，底层就是 yield return：

```csharp
public static IEnumerable<T> Where<T>(this IEnumerable<T> source, Func<T, bool> predicate) {
    foreach (var item in source) {
        if (predicate(item)) yield return item;   // ← 就是这个 yield
    }
}
```

### 5.7 异步流 IAsyncEnumerable + await foreach

yield 的异步版，迭代过程中可以 await：

```csharp
async IAsyncEnumerable<int> ReadAsync() {
    for (int i = 0; i < 100; i++) {
        await Task.Delay(10);    // 异步操作（读数据库/网络）
        yield return i;          // 异步流式返回
    }
}

await foreach (var n in ReadAsync()) { ... }
```

- `IAsyncEnumerable<T>`：异步版 IEnumerable
- `async IAsyncEnumerable<T>` 方法里可以 await + yield return 混用
- 用途：异步流式处理大数据（EF Core 流式查询、逐批读网络流）

### 5.8 陷阱：重复迭代会重新执行

```csharp
IEnumerable<int> GetNums() {
    Console.WriteLine("开始执行！");
    yield return 1;
    yield return 2;
}

var nums = GetNums();
nums.ToList();   // 打印一次"开始执行"
nums.ToList();   // 又打印一次！—— 方法体重新跑了一遍
```

原因：yield 惰性，每次 foreach 都重新执行方法体。结果要重复用时先 ToList 物化。

### 5.9 IEnumerable vs IEnumerator

| | 角色 | 关键成员 |
|---|---|---|
| IEnumerable<T> | 序列（可被遍历） | GetEnumerator() |
| IEnumerator<T> | 游标（正在遍历） | MoveNext() + Current |

foreach 底层：

```csharp
using var e = list.GetEnumerator();
while (e.MoveNext()) {
    var item = e.Current;
}
```

### 5.10 何时 ToList 缓存 vs 流式

| 场景 | 做法 |
|------|------|
| 结果只消费一次 / 数据量大 | 保持流式，边读边处理 |
| 结果要重复用多次 | 先 ToList 物化一次，避免重复计算 |

## 6. 事件（Event）

### 6.1 事件是什么：发布-订阅模式

对象"通知"外部发生了某事，外部"订阅"通知：

```csharp
public class Button {
    public event EventHandler? Clicked;          // ① 声明事件
    public void Press() {
        Clicked?.Invoke(this, EventArgs.Empty);  // ② 触发（通知所有订阅者）
    }
}

var btn = new Button();
btn.Clicked += (s, e) => Console.WriteLine("被点击了！");   // ③ 订阅
btn.Press();   // 输出"被点击了！"
```

### 6.2 event 是委托的"受限版"

事件底层就是委托，但加了封装。核心限制：**事件只能由声明它的类触发，外部只能 += / -= 订阅取消，不能触发、不能清空。**

```csharp
Clicked?.Invoke(this, EventArgs.Empty);   // ✅ 类内部可以触发
btn.Clicked += handler;    // ✅ 外部订阅
btn.Clicked -= handler;    // ✅ 外部取消订阅
btn.Clicked.Invoke(...);   // ❌ 编译报错！外部不能触发
```

### 6.3 委托字段 vs 事件

| | 普通委托字段 | 事件 |
|---|---|---|
| 外部订阅 += | ✅ | ✅ |
| 外部触发 Invoke | ✅（危险） | ❌ 禁止 |
| 外部清空 = null | ✅（危险） | ❌ 禁止 |

一句话：**事件 = 封装了"触发权"的委托**。

### 6.4 .NET 标准事件签名

```csharp
public event EventHandler? Clicked;              // 无参数
public event EventHandler<MyArgs>? Completed;    // 带自定义参数
```

- `EventHandler` = `void (object sender, EventArgs e)`
- `sender`：谁触发的；`EventArgs`/`MyArgs`：事件数据

### 6.5 应用场景

| 场景 | 例子 |
|------|------|
| UI | 按钮 Clicked、文本框 TextChanged |
| 定时器 | Timer.Elapsed |
| ASP.NET Core 生命周期 | IHostApplicationLifetime 的 ApplicationStarted / Stopping |
| 后台任务优雅关闭 | HostedService 注册 CancellationToken 回调 |

## 9. Span / 性能

### 9.1 问题的起点：`Substring` 在偷偷分配内存

`string` 不可变，每次 `Substring` 都**分配一个全新的字符串**并拷贝字符：

```csharp
string date = "2026-08-14";
string year = date.Substring(0, 4);   // 分配新字符串 "2026"
string month = date.Substring(5, 2);  // 又分配 "08"
```

- 你项目 `ReportService.cs` 有 20+ 处 `dateString.Substring(0, 4)` 这类日期/周解析
- 每次调用都产生一个短命字符串 → 大量垃圾进 0 代 → GC 压力

**如果只是"看一眼"某段字符（解析、比较），根本不需要分配新字符串——这就是 Span 的用武之地。**

### 9.2 `Span<T>`：不拥有内存的"视图"

`Span<T>` 是一个 `ref struct`（值类型），内部只有两样东西：**一个指针 + 一个长度**。

- 它**不拥有**内存，只是"看"一段连续内存
- 可以指向：数组、字符串、`stackalloc` 栈内存、非托管内存

```csharp
string s = "hello world";
ReadOnlySpan<char> span = s.AsSpan();        // 整个字符串的只读视图
ReadOnlySpan<char> slice = span.Slice(0, 5); // "hello"，零分配
```

### 9.3 零分配切片 vs Substring

```
Substring：  旧串 [h][e][l][l][o][ ][w][o][r][l][d]
                   │ 拷贝 5 个字符
                   ▼
             新串 [h][e][l][l][o]   ← 新分配的堆对象

Span.Slice： 同一块内存
             [h][e][l][l][o][ ][w][o][r][l][d]
              ▲─────────────▲
              │ 指针偏移，长度 5 │   ← 不分配、不拷贝，只是换视角
```

- `Substring`：分配 + 拷贝 → 新堆对象
- `Span.Slice`：只移动指针、改长度 → **零分配、零拷贝**

### 9.4 Span 是 `ref struct`：只能活在栈上

`Span` 被设计成 `ref struct`，**保证它永远不逃出栈帧**——这样才能安全地"借"内存而不怕悬空引用。代价是很多限制：

| 操作 | 是否允许 |
|---|---|
| 局部变量、方法参数 | ✅ |
| 作为 class 的字段 | ❌（会逃到堆上） |
| 装箱（`object o = span`） | ❌ |
| 跨 `async/await` | ❌（await 可能切线程/栈帧） |
| 捕获进 Lambda / LINQ | ❌ |
| 泛型参数（`List<Span<T>>`） | ❌（.NET 9 前） |

```csharp
// ❌ 编译错误：Span 不能跨 await
async Task<int> Bad() {
    ReadOnlySpan<char> s = "...".AsSpan();
    await Task.Delay(1);
    return s.Length;   // 编译器报错
}
```

### 9.5 `stackalloc`：栈上直接分配数组

```csharp
Span<int> nums = stackalloc int[3] { 1, 2, 3 };  // 栈上分配，绕过堆和 GC
```

- 直接在**栈**上分配，不经过堆、不产生 GC 垃圾
- ⚠️ 栈只有 1MB 左右，`stackalloc` 分配太大会 `StackOverflow`，只适合小块数据

### 9.6 `Memory<T>`：能跨异步的 Span

`Span` 不能跨 `async`，那异步场景怎么办？用 `Memory<T>`：

| | `Span<T>` | `Memory<T>` |
|---|---|---|
| 类型 | `ref struct`（只能栈上） | 普通 `struct`（可进堆） |
| 跨 async | ❌ | ✅ |
| 性能 | 最高 | 略低（取出 Span 再操作） |

```csharp
Memory<byte> buffer = new byte[1024];      // Memory 可跨 async
ReadOnlySpan<byte> span = buffer.Span;     // 用时取出 Span 零分配操作
```

**分工**：同步代码用 `Span`，异步代码用 `Memory`（要操作时再 `.Span` 取出）。

### 9.7 项目实景：哪些 `Substring` 能用 Span

你项目里的典型可优化场景：

```csharp
// ReportService.cs：日期解析（每次 3 次 Substring = 3 个新字符串）
DateTime date = new DateTime(
    Convert.ToInt32(dateString.Substring(0, 4)),
    Convert.ToInt32(dateString.Substring(4, 2)),
    Convert.ToInt32(dateString.Substring(6, 2)));
```

如果只做解析（不保存切片结果），可以用 Span 零分配：

```csharp
ReadOnlySpan<char> s = dateString.AsSpan();
int year = int.Parse(s.Slice(0, 4));
int month = int.Parse(s.Slice(4, 2));
int day = int.Parse(s.Slice(6, 2));
```

⚠️ 但要注意：**如果切片结果要长期保存、作为返回值、跨方法传递，Span 就不能用了**（它不能逃出栈帧），此时还是得老老实实 `Substring`。

### 9.8 什么时候用、什么时候别用

| 场景 | 用 Span？ |
|---|---|
| 高频字符串切片（解析、比较） | ✅ 用 |
| 字节/缓冲区处理（文件、网络） | ✅ 用 |
| 结果要长期保存或跨异步 | ❌ 用 `Substring` / `Memory<T>` |
| 普通业务代码，没性能问题 | ❌ 别为用而用 |

**原则**：Span 是"性能优化工具"，不是"日常默认写法"。先测量（第 7 课原则），确认有分配热点再上 Span。

### 9.9 小结

| 概念 | 一句话 |
|---|---|
| `Span<T>` | 连续内存的零分配"视图"（指针 + 长度） |
| `ref struct` | 只能活在栈上，所以安全 |
| `stackalloc` | 栈上直接分配，绕过 GC |
| `Memory<T>` | 跨异步的 Span |

> 一句话：**Span 不复制数据，只是"换视角"看内存——切片、解析、遍历都零分配，把 GC 压力降到最低。**
