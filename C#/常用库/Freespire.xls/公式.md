# FreeSpire.XLS 公式（Formula）处理笔记

> 库：`FreeSpire.XLS`（免费版，NuGet 包 `FreeSpire.XLS`）
> 版本：`16.4.0`（netstandard2.0 / net48）
> 命名空间：`Spire.Xls`
> 整理日期：2026-08-27
> 说明：本文基于**反编译（反射）** `Spire.XLS.dll` 实证，非文档摘抄。

---

## 一、核心结论（踩坑结论）

**FreeSpire 在"读模板 → 写数据 → 保存"时不会自动重算公式。**
带公式（计算属性）的模板，写完数据后如果不显式调用计算 API，公式单元格的**缓存结果不会刷新**——程序读回拿到的是旧值/空值。

**解决方法：保存前显式调用 `Workbook.CalculateAllValue()`。**

---

## 二、公式相关 API 一览（反编译实证）

来源：`Spire.Xls.Workbook` 公开成员。

| 成员 | 签名 | 作用 |
| --- | --- | --- |
| `CalculateAllValue` | `void CalculateAllValue()` | **一键计算工作簿全部公式**（最常用） |
| `CalculateFormulaValue` | `object CalculateFormulaValue(string text)` | 计算单个公式文本，返回结果 |
| `CaculateFormulaValue` | `object CaculateFormulaValue(string text)` | 同上（**注意拼写少一个 l**，是重载/历史遗留） |
| `CalculationMode` | `ExcelCalculationMode get/set` | 计算模式（见下） |
| `RecalculateOnOpen` | `bool get/set` | 是否在 Excel 打开时重算 |
| `MaxRowsOfSharedFormula` | get/set | 共享公式最大行数 |

### 计算模式枚举 `Spire.Xls.ExcelCalculationMode`

| 值 | 含义 |
| --- | --- |
| `Manual` | 手动计算（默认？需按需设置） |
| `Auto` | 自动计算 |
| `AutoNoTable` | 自动计算但不含表格 |

## 三、典型用法（模板写数据后刷新公式）

```csharp
using Spire.Xls;

var workbook = new Workbook();
workbook.LoadFromFile(templatePath);          // 打开带公式的模板

// ... 往单元格写数据 ...

// 关键：保存前显式重算公式
workbook.CalculationMode = ExcelCalculationMode.Auto; // 可配合设置
workbook.CalculateAllValue();                          // ← 刷新所有公式结果

workbook.SaveToFile(outputPath, ExcelVersion.Version2016);
```

### 只算单个公式

```csharp
object result = workbook.CalculateFormulaValue("SUM(A1:A10)");
// 或拼写变体
// object result = workbook.CaculateFormulaValue("SUM(A1:A10)");
```

## 四、与 ClosedXML 的对照（我平时用的库）

| 场景 | ClosedXML | FreeSpire.XLS 16.4.0 |
| --- | --- | --- |
| **保存时是否自动重算** | ✅ **自动**（`Save()` 时重算公式并写入结果） | ❌ **不自动**，必须显式调 `CalculateAllValue()` |
| 重算全部公式（手动） | `workbook.RecalculateAllFormulas()` | `Workbook.CalculateAllValue()` |
| 计算单个公式 | 保存后读 `cell.Value` | `Workbook.CalculateFormulaValue(...)` |
| 透视表支持 | ❌ 差（不支持创建透视表） | ✅ 支持（项目透视表导出在用） |

> **关键差异**：ClosedXML 省心（保存自动算公式），但做不了透视表；FreeSpire 要手动重算，但透视表可以。**这正是当初透视表需求选 FreeSpire 而不是 ClosedXML 的原因。**

> 另：项目里还有 NPOI（`STCommon/ExcelHandle.cs`，短脉冲 RB 文件），行为和 FreeSpire 一样——保存不自动重算；且现有 NPOI 写入已成型，不建议用 ClosedXML 重构。

## 五、踩坑 & 注意事项

1. **写数据后公式不刷新 = 忘了调 `CalculateAllValue()`**，不是库不支持。
2. **"程序读回公式结果" ≠ "人打开 Excel 看到的结果"**：
   - Excel/WPS 打开文件时通常会自动重算（公式是活的），"给人看"没问题；
   - 但**程序自己读回公式单元格**时拿的是缓存值，必须显式重算后再读。
3. **公式引擎覆盖有限**：FreeSpire（和 NPOI）对复杂函数/数组公式支持不完整。若模板公式太复杂、算不出正确结果，校验逻辑应改用 C# 自己实现（规则配置化），不要硬依赖公式引擎。
4. `CalculateFormulaValue` / `CaculateFormulaValue` 两个拼写都存在（少一个 l 的那个是变体），用哪个都行，但注意别记混。
5. 若要在**程序内读回公式结果做业务判断**，顺序应为：写数据 → `CalculateAllValue()` → 再读单元格。
