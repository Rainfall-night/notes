## 1. 类型系统（值类型 vs 引用类型）

C# 所有类型分两派：


|        | 值类型（Value Type）                             | 引用类型（Reference Type）              |
| -------- | -------------------------------------------------- | ----------------------------------------- |
| 关键字 | `int` `double` `bool` `DateTime` `struct` `enum` | `string` `class` `interface` `delegate` |
| 存什么 | 存**值本身**                                     | 存**地址（引用）**                      |
| 默认值 | 有非 null 默认值（`int`→0，`bool`→false）      | 默认是`null`                            |
| 复制时 | 复制一份值（互不影响）                           | 复制地址（指向同一个对象）              |

### 1.0 常用基础数据类型

**值类型**（先认识这些"砖头"）：


| 类型             | 含义                 | 项目里的用法                              |
| ------------------ | ---------------------- | ------------------------------------------- |
| `int`            | 32 位整数            | 状态码`State`、数量 `Count`               |
| `long`           | 64 位整数            | 主键`ID`（工单/用户/日志 ID）             |
| `short` / `byte` | 16 位 / 8 位整数     | 少用                                      |
| `double`         | 双精度浮点           | `remaining` 剩余分钟、TAT                 |
| `float`          | 单精度浮点           | 少用                                      |
| `decimal`        | 高精度小数           | 花费`AccomplishSpending`（工时/金额）     |
| `bool`           | 布尔 true/false      | `IfLIVTest` 等测试标记                    |
| `char`           | 单个字符             | 少用                                      |
| `DateTime`       | 日期时间             | `CreateTime`、`ModifyTime`                |
| `enum`           | 枚举（一组命名常量） | `EnumWorkOrderState`、`EnumProcedureName` |
| `struct`         | 自定义值类型         | 少用                                      |

**引用类型**：


| 类型                               | 含义                     |
| ------------------------------------ | -------------------------- |
| `string`                           | 字符串（内容**不可变**） |
| `object`                           | 所有类型的基类           |
| `class` / `interface` / `delegate` | 自定义引用类型           |

**为什么金额/工时用 `decimal` 不用 `double`**：`double` 是二进制浮点，`0.1 + 0.2 != 0.3`（精度丢失）；`decimal` 是十进制精确表示，金额/工时计算必须用它。项目里花费字段 `AccomplishSpending`、`TotalRunSpending` 就是 `decimal`。

### 1.1 复制行为的区别

```csharp
// 值类型：复制值，互不影响
int a = 10;
int b = a;      // b 复制了 10
b = 99;
// a 还是 10

// 引用类型：复制地址，指向同一个对象
var list1 = new List<int> { 1, 2, 3 };
var list2 = list1;   // list2 复制的是"地址"
list2.Add(4);
// list1 也变成 {1,2,3,4} —— 它们是同一个对象
```

### 1.2 `null` 只属于引用类型

- 值类型**天生不能是 null**（`int x = null;` 编译报错）
- 引用类型可以 null（`string s = null;` 合法）

### 1.3 可空值类型 `int?`

值类型要表达"没有值"时，加 `?`：

```csharp
int? count = null;          // 本质是 Nullable<int>
bool? flag = null;          // 三态：true / false / null
DateTime? time = null;
```

### 1.4 解释项目里的 SQL NULL 坑

数据库列允许 NULL，但 C# 的 `int`/`bool` 天生不能装 null。项目里 `WorkOrderEntity` 字段写成：

```csharp
public int? State { get; set; }          // 列可能 NULL → int?
public string? ProjectName { get; set; } // 列可能 NULL → string?
public bool? IfLIVTest { get; set; }     // 列可能 NULL → bool?
```

之前 `SqlNullValueException` 就是 DB 返回 NULL 往非空 `int`/`bool` 里塞直接炸，全改可空后类型才能装下 NULL。

### 1.5 `var` 类型推断

```csharp
var sql = @"...";                       // 编译器推断 string
var rawList = await _repo.GetRaw...();  // 推断 List<WorkOrderRaw>
var parameters = new List<object>();    // 推断 List<object>
```

- `var`：让编译器根据右侧表达式**自动推断类型**
- 编译期就确定类型（不是动态类型），运行时无损耗
- 好处：类型名长时简洁；项目里满屏 `var`

### 1.6 装箱与拆箱

值类型和引用类型之间的转换：

```csharp
int i = 10;
object o = i;        // 装箱：值类型 int → object（栈搬到堆）
int j = (int)o;      // 拆箱：object → int（堆搬回栈）
```

- **装箱**：值类型 → object（产生堆分配，有性能损耗）
- **拆箱**：object → 值类型（需强转）
- 尽量用泛型 `List<int>` 代替 `List<object>` 避免装箱——这正是泛型（第 5 课）的价值之一

### 1.7 字符串与字符串插值 `$"..."`

```csharp
string s = $"当前时间 {DateTime.Now}";
string t = $"{tatHours:F1}小时";   // :F1 保留 1 位小数
string p = $"{{{i}}}";             // {{ 转义成单个 {
```

- `$"..."`：字符串里用 `{}` 嵌入表达式
- `{{` / `}}` 转义成 `{` / `}`
- 项目例子：`$"{tatHours:F1}小时"`、`$"AND ... IN ({string.Join(",", placeholders)})"`

## 2. 可空引用类型（NRT）+ null 处理操作符

### 2.1 可空引用类型（NRT）

C# 8.0 引入，**编译期** null 安全机制（运行时无区别）：

```csharp
string name = "abc";      // 非空引用：编译器认为不会是 null
string? nickName = null;  // 可空引用：明确允许 null
```

作用：把"可能为 null"从运行时崩溃提前到编译时警告。`.csproj` 开 `<Nullable>enable</Nullable>` 后，引用类型默认要求非空，允许 null 必须显式写 `?`。

### 2.2 `??` 空合并：null 就给默认值

```csharp
w.ProjectName ?? ""      // null 时返回 ""
raw.ConsoleCode ?? ""
```

项目里 `wo.CreateUserName ?? ""` 满屏都是——DB 可能返回 NULL，展示时兜底成空串。

### 2.3 `?.` 空条件：null 就短路，否则取成员

```csharp
user?.Name              // user 为 null → 整个表达式 null
list?.Count
```

常与 `??` 连用：`user?.Name ?? "匿名"`。

### 2.4 `!` 空原谅：告诉编译器"保证非 null，别警告"

```csharp
var parsed = rawList
    .Select(w => ParseWorkOrder(w))   // 返回 WorkOrderParsed?（可空）
    .Where(w => w != null)            // 过滤掉 null
    .Select(w => w!)                  // 已保证非 null
    .ToList();
```

`Where(w => w != null)` 编译器看不出保证，需 `w!` 手动声明。

### 2.5 相关姿势

```csharp
name ??= "默认值";   // 空合并赋值，等价 if (name == null) name = "默认值";

// 可空值类型取值：先 HasValue 再 .Value
DateTime? next = raw.NextStepStartTime;
if (next.HasValue) {
    var t = next.Value.AddHours(8);   // .Value 取出真正的 DateTime
}
```

### 2.6 三元运算符 `?:`

```csharp
condition ? a : b     // 条件为真返回 a，否则返回 b
```

项目例子：

```csharp
minRemaining.HasValue ? Math.Round(minRemaining.Value, 0) : null
g.Any() ? "running" : "idle"
```

本质是 if/else 的**表达式**版（有返回值），`??` 其实是它的 null 特化。

### 2.7 switch 表达式

```csharp
w.Priority switch {
    1 => "P1",
    2 => "P2",
    3 => "P3",
    _ => ""        // _ 是"弃元"，默认分支
}
```

- 比 switch 语句更简洁的"表达式"写法
- `_` 匹配任何值（默认分支）
- 项目例子：`Priority = w.Priority switch { 1 => "P1", 2 => "P2", 3 => "P3", _ => "" }`

## 3. 类、属性、方法、构造函数

### 3.1 class 是图纸，object 是产品

```csharp
public class User {
    public string Name { get; set; }
}
User u = new User();   // new 按"图纸"造出实例
```

- class：类型定义（模板）
- object/instance：`new` 造出的实例，一个 class 可 `new` 出无数个对象

### 3.2 字段 vs 属性

```csharp
private readonly AppDbContext _db;   // 字段：私有，存数据
public long ID { get; set; }         // 属性：带 get/set 的访问器
```


|      | 字段              | 属性                         |
| ------ | ------------------- | ------------------------------ |
| 写法 | `private int _x;` | `public int X { get; set; }` |
| 本质 | 变量              | get/set 方法的语法糖         |
| 惯例 | 私有（`_` 前缀）  | 公开                         |

### 3.3 自动属性

```csharp
public string Name { get; set; }   // 编译器自动生成隐藏字段
public string Name { get; }        // 只读属性，仅构造函数可赋值
```

### 3.4 只读字段 + 构造函数注入（项目核心模式）

```csharp
public class MachineMonitorRepository {
    private readonly AppDbContext _db;                // 只读字段

    public MachineMonitorRepository(AppDbContext db) { // 构造函数
        _db = db;                                     // 存依赖
    }
}
```

- `readonly`：仅声明时或构造函数赋值一次，之后不可改
- **构造函数注入**：依赖经构造函数传入存字段，DI 容器自动 `new` 并传参（`Program.cs` 里 `AddScoped` 注册后生效）

### 3.5 构造函数 / 方法 / 可选参数

```csharp
// 构造函数：方法名=类名，无返回值类型，new 时自动调用，可重载
public MachineMonitorRepository(AppDbContext db) { _db = db; }

// 方法：返回类型 + 方法名 + 参数；= null 是可选参数默认值
public async Task<List<WorkOrderRaw>> GetRawWorkOrdersAsync(List<string>? machineNames = null)
```

### 3.6 访问修饰符


| 修饰符      | 可见范围                          |
| ------------- | ----------------------------------- |
| `public`    | 任何地方都能访问                  |
| `private`   | 仅当前类内部                      |
| `protected` | 当前类 + 派生类（子类）           |
| `internal`  | 同一程序集（同一个项目/编译单元） |

项目惯例：字段 `private`，属性/方法 `public`。

### 3.7 `static` 静态成员 vs 实例成员

```csharp
public class ExecuteResult {
    public bool Success { get; set; }   // 实例成员：要 new 出来才能用

    public static ExecuteResult Ok(string message = "") => new() { ... };  // 静态：用类名调用
}

ExecuteResult.Ok("ok");        // 静态：类名.方法，不用 new
var r = new ExecuteResult();   // 实例：先 new
r.Success = true;
```

- 静态成员属于**类**，实例成员属于**对象**
- 项目例子：`ExecuteResult<T>.Ok(cards)`、`PagedList<T>.Create(...)`、`EnumHelper.GetDescriptionByEnum(...)`

### 3.8 `const` vs `readonly`


|          | `const`                         | `readonly`                           |
| ---------- | --------------------------------- | -------------------------------------- |
| 性质     | 编译期常量                      | 运行时常量                           |
| 赋值     | 声明时必须赋值                  | 声明时或构造函数赋值                 |
| 类型     | 仅基本类型/字符串               | 任意类型                             |
| 项目例子 | `ResponseCodes.Success = 20000` | `private readonly AppDbContext _db;` |

### 3.9 表达式体成员 `=>`

方法或属性体只有一个表达式时，用 `=>` 简写：

```csharp
// 表达式体方法
bool IsEven(int x) => x % 2 == 0;
// 等价于
bool IsEven(int x) { return x % 2 == 0; }

// 表达式体属性（只读）
public bool Visible => true;
```

项目里委托示例、`ExcelVisibleAttribute.Visible` 都用了这个语法。

### 3.10 `new()` 目标类型推断

```csharp
List<int> list = new List<int>();   // 完整写法
List<int> list = new();             // new()：左侧类型已知，省略右侧类型名
```

项目例子：`ExecuteResult.Ok(...) => new() { Success = true, ... }`。

## 4. 接口、继承、多态

### 4.1 继承 `:`（代码复用）

```csharp
// 基类：公共字段
public class Entity {
    public long ID { get; set; }
    public bool IsDelete { get; set; }
    public long? Modifier { get; set; }
    public DateTime? ModifyTime { get; set; }
}

// 子类：自动拥有上面 4 个字段
public class WorkOrderEntity : Entity {
    public string? WorkOrderCode { get; set; }
}
```

- `:` 表示继承，子类自动拥有父类所有成员
- 项目例子：`WorkOrderEntity : Entity`、`WorkOrderLogEntity : Entity`、`ExecuteResult<T> : ExecuteResult`、`RbMachineDetailDto : RbMachineCardDto`

### 4.2 接口（契约）

```csharp
public interface IEntity {
    public void InitID();   // 只有签名，没有实现
}
```

- 契约：定义"能做什么"，不定义"怎么做"
- 实现接口的类必须实现所有接口成员；接口不能有字段、不能 `new`

### 4.3 继承 vs 接口


|      | 继承`: 类`         | 实现`: 接口`     |
| ------ | -------------------- | ------------------ |
| 关系 | is-a（是一个）     | can-do（能做）   |
| 数量 | 只能继承一个类     | 可实现多个接口   |
| 内容 | 有实现（代码复用） | 只有签名（契约） |

一句话：**继承复用"代码"，接口约定"能力"。**

### 4.4 多态 + virtual / override

```csharp
public class Animal {
    public virtual void Speak() => Console.WriteLine("...");   // 允许重写
}
public class Dog : Animal {
    public override void Speak() => Console.WriteLine("汪汪");  // 重写
}
Animal a = new Dog();
a.Speak();   // "汪汪" —— 按实际类型执行，不是声明类型
```

- `virtual`：父类标记可重写；`override`：子类重写
- 项目例子：`ExecuteResult.Set` 是 `virtual`，为子类重写预留

### 4.5 面向对象三大特性


| 特性 | 含义                | 项目例子                             |
| ------ | --------------------- | -------------------------------------- |
| 封装 | 字段私有 + 属性公开 | `private readonly AppDbContext _db;` |
| 继承 | 子类复用父类        | `WorkOrderEntity : Entity`           |
| 多态 | 同一接口不同实现    | `ExecuteResult.Set` 的 virtual       |

### 4.6 `abstract` 抽象类与抽象方法

```csharp
public abstract class Animal {       // 抽象类：不能 new
    public abstract void Speak();    // 抽象方法：只有签名，子类必须 override
}

public class Dog : Animal {
    public override void Speak() => Console.WriteLine("汪汪");
}
```

- `abstract` 类不能实例化（`new Animal()` 编译报错），只能被继承
- `abstract` 方法没有实现体，子类必须 `override` 实现
- 作用：定义"模板"，强制子类实现约定

## 5. 泛型

### 5.1 为什么需要泛型

一个类/方法适用于多种类型，编译器保证类型安全。

```csharp
// 没有泛型（object）：什么都能塞，取出要强转，错了运行时才崩
List list = new List();
list.Add(1);
list.Add("abc");
int x = (int)list[0];

// 有泛型：类型安全，不用强转
List<int> list = new List<int>();
list.Add(1);
// list.Add("abc");   // 编译报错
int x = list[0];
```

### 5.2 泛型类 `class Xxx<T>`

```csharp
public class ExecuteResult<T> : ExecuteResult {
    public T? Data { get; set; }   // T 是占位符，调用时填具体类型
}

ExecuteResult<List<RbMachineCardDto>> result;  // T = List<RbMachineCardDto>
```

项目里的泛型类：`ExecuteResult<T>`、`PagedList<T>`、`ResponseResult<T>`。

### 5.3 泛型集合

```csharp
List<string> names;
Dictionary<string, string> extend;   // 键值对
// 项目例子：ExecuteResult.ExtendData、PagedList.ExtendData
```

### 5.4 泛型方法

```csharp
_db.Set<WorkOrderRaw>()   // Set<T>，T = WorkOrderRaw，返回 DbSet<WorkOrderRaw>
    .FromSqlRaw(sql, ...)
```

### 5.5 泛型约束 `where T : ...`

```csharp
public static string GetDescriptionByEnum<T>(int enumValue) where T : Enum {
    // where T : Enum —— T 必须是枚举，才能用 Enum.GetName(typeof(T), ...)
}
```

约束让编译器知道 `T` 至少具备哪些能力。

**一句话：泛型 = 用 T 占位类型，调用时填具体类型，编译器全程保证类型安全，避免强转和运行时错误。**

## 6. 委托、Lambda、LINQ

### 6.1 委托：把方法当参数传

```csharp
delegate bool Filter(int x);          // 委托：指向方法的类型
bool IsEven(int x) => x % 2 == 0;
Filter f = IsEven;
bool result = f(4);                   // 调用委托 = 调用方法
```

### 6.2 内置委托 Func / Action

```csharp
Func<int, bool> isEven = x => x % 2 == 0;   // 有返回值，最后一个是返回类型
Action<string> print = s => Console.WriteLine(s);  // 无返回值
```

### 6.3 Lambda 表达式

```csharp
// 完整匿名方法
Func<int, bool> f = delegate(int x) { return x % 2 == 0; };
// Lambda 简写（等价）
Func<int, bool> f = x => x % 2 == 0;
```

语法：`参数 => 表达式`，`=>` 读作 goes to。

### 6.4 LINQ 常用方法


| 方法                        | 作用       | 项目例子                            |
| ----------------------------- | ------------ | ------------------------------------- |
| Where                       | 过滤       | `.Where(w => w != null)`            |
| Select                      | 投影/转换  | `.Select(w => ParseWorkOrder(w))`   |
| OrderBy / OrderByDescending | 排序       | `.OrderBy(w => w.RemainingMinutes)` |
| GroupBy                     | 分组       | `.GroupBy(w => w.ConsoleCode)`      |
| First / FirstOrDefault      | 取第一个   | `.FirstOrDefault(...)`              |
| Any                         | 是否有元素 | `g.Any()`                           |
| Count / Sum / Min / Max     | 聚合       | `remainingValues.Min()`             |
| ToList                      | 转 List    | `.ToList()`                         |
| Contains                    | 包含       | `ids.Contains(...)`                 |
| Distinct                    | 去重       | `.Distinct()`                       |

### 6.5 项目真实 LINQ 链拆解

```csharp
var parsed = rawList
    .Select(w => ParseWorkOrder(w))   // ① 解析成 WorkOrderParsed?
    .Where(w => w != null)            // ② 过滤 null
    .Select(w => w!)                  // ③ 声明非 null
    .ToList();                        // ④ 转 List
```

### 6.6 链式调用 + 延迟执行

- 链式调用：每个方法返回新集合，一路 `.` 下去
- 延迟执行：Where/Select 不立刻跑，直到 ToList()/foreach 才执行（EF Core 章节讲 IQueryable 会再见）

## 7. async / await

### 7.1 同步 vs 异步

- 同步：一件事做完再做下一件（线程干等，阻塞）
- 异步：发起耗时操作后不干等，线程去做别的，完成再回来

类比烧水：同步=站水壶旁干等；异步=放上水壶去切菜，水开再回来。

### 7.2 Task<T></t>

```csharp
Task<List<WorkOrderRaw>>   // 将来返回 List<WorkOrderRaw> 的操作
Task                       // 将来完成、不返回值
```

### 7.3 async / await 语法

```csharp
public async Task<List<WorkOrderRaw>> GetRawWorkOrdersAsync(...) {
    return await _db.Set<WorkOrderRaw>()
        .FromSqlRaw(sql, parameters.ToArray())
        .AsNoTracking()
        .ToListAsync();   // await：等查询完成，不阻塞线程
}
```

- `async`：标记方法里用了 await
- `await`：等异步操作完成拿结果，不阻塞线程

### 7.4 async 会传染

async 方法只能被 await 调用，所以 async 从 Repository → Service → Controller 一路传染：

```csharp
// Repository
public async Task<List<WorkOrderRaw>> GetRawWorkOrdersAsync(...)
// Service
public async Task<ExecuteResult<...>> GetCardsAsync(...) { await _repo.GetRawWorkOrdersAsync(...); }
// Controller
public async Task<ExecuteResult<...>> GetCards(...) { return await _service.GetCardsAsync(...); }
```

### 7.5 异步的坑


| 坑                    | 说明                                 |
| ----------------------- | -------------------------------------- |
| `async void`          | 异常无法捕获，避免（仅事件处理器用） |
| `.Result` / `.Wait()` | 同步阻塞，可能死锁，避免             |

老 MES 坏味道：`_workOrderLogRepo.Select(...).Result`（同步阻塞）。
正确写法：`await _db.Set<WorkOrderRaw>()...ToListAsync()`。

### 7.6 为什么 Web 应用要异步

线程数有限：同步阻塞时线程干等 → 高并发下线程耗尽；异步等 IO 时线程被释放处理其他请求 → 同线程数扛更多并发。
