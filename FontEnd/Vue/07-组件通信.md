# 组件通信

> 基于 MES 前端项目 `STwebsiteFrontEnd_V1` 的实际代码

---

## 一、Props 下传 / $emit 上传 — 父子通信

```
父组件（TEST_LIV/index.vue）
    │
    │  props ↓              $emit ↑
    │                    ("我完成了，刷新")
    └── 子组件（checkin.vue / checkout.vue）
```

### 父传子 — props

```vue
<!-- TEST_LIV/index.vue（父） -->
<checkin-dialog
  :operate-id="formStatus.operateId"    ← 传数据下去
  :params="formStatus.params"
  :form-type="formStatus.formType"
  @form-checkined="handleCheckIned"     ← 收事件上来
/>
```

```js
// checkin.vue（子）接收
export default {
  props: {
    operateId: String,    // 父传下来的工单ID
    params: Object,       // 父传下来的额外参数
    formType: String      // checkin / checkout
  }
}
```

> `props` 是 `export default` 的顶级选项，详见 [[03-单文件组件#四、export default 组件选项完整清单|组件选项清单]]。

### 子传父 — $emit

```js
// checkin.vue（子）通知父
this.$emit('form-checkined', 'done')   // 告诉父："我完成了"
```

```js
// TEST_LIV/index.vue（父）处理
handleCheckIned(val) {
    if (val === 'done') {
        this.fetchData()               // 子完成后，父刷新数据
    }
}
```

## 二、Vuex — 跨层级全局共享

```
     Layout
    /   |   \
Navbar  Sidebar  AppMain(→具体页面)
    \   |   /
     Vuex Store（全局仓库）
```

所有组件都能直接读写，不需要层层传递 props。

```js
// Sidebar 中读
this.$store.state.app.sidebar.opened

// Navbar 中改
this.$store.dispatch('app/toggleSideBar')

// ResizeHandler 中改
store.dispatch('app/toggleDevice', 'mobile')
```

> Vuex 是独立的大话题，详见 [[09-Vuex]]。

## 三、eventBus — 兄弟/任意组件通信（本项目少用）

```js
// 发送方
this.$bus.$emit('refresh-data')

// 接收方
this.$bus.$on('refresh-data', () => { this.fetchData() })
```

本项目基本都用 Vuex 替代了 eventBus。

## 四、三种方式对比

| 方式 | 方向 | 适用场景 | 本项目用法 |
|------|------|----------|-----------|
| props / `$emit` | 父子单向 | 弹窗传参、结果回传 | checkin/checkout |
| Vuex | 任意组件 | 全局状态 | 侧边栏、用户角色 |
| eventBus | 任意组件 | 轻量事件 | 很少用 |

## 五、provide/inject — 跨层级依赖注入

### 它解决什么问题？

当组件层级很深时，props 需要逐层传递——每一层都要声明 props 然后往下传，中间组件只是"快递员"，自己不消费数据：

```
Page
  └─ FormPanel        ← 声明 props，往下传
       └─ FormItem    ← 声明 props，往下传
            └─ MyInput  ← 真正需要数据的地方
```

**provide/inject** 让祖先直接"提供"数据，任意后代直接"注入"消费——跳过中间层。

### 基本语法

```vue
<!-- ===== 祖先组件 Page.vue ===== -->
<script>
export default {
  provide() {                           // 必须是函数，才能访问 this
    return {
      theme: this.theme,
      // 传整个实例是最常见的实战用法
      ancestor: this
    }
  },
  data() {
    return { theme: 'dark' }
  }
}
</script>

<!-- ===== 深层后代 MyInput.vue（中间隔了无数层） ===== -->
<script>
export default {
  inject: ['theme', 'ancestor'],        // 直接注入，中间组件什么都不用写
  mounted() {
    console.log(this.theme)             // 'dark'
    this.ancestor.fetchData()           // 可以调祖先的方法
  }
}
</script>
```

### 关键限制：Vue 2 中 provide 默认**不是响应式的**

```js
// ❌ 这样写，祖先改了 theme，后代会收不到更新
provide() {
  return { theme: this.theme }          // 传的是当时值的快照
}
```

因为 `provide` 在组件初始化时只执行一次，传进去的是**当时的值**，后续 `this.theme` 变了，注入方拿到的还是旧值。

**实战中的解决方案 — 传入组件实例 `this`：**

```js
// 祖先
provide() {
  return { ancestor: this }             // 把整个实例传下去
}

// 后代
inject: ['ancestor'],
// 通过 ancestor.xxx 访问的都是响应式数据（因为 ancestor 就是那个活的组件实例）
this.ancestor.theme                     // ✅ 响应式
this.ancestor.fetchData()               // ✅ 能调方法
```

> 这种用法在你项目的工序页面中可能出现——父组件把 `this` provide 下去，子组件通过 injected 的 `ancestor` 访问数据和方法。

### inject 的进阶写法

```js
// 简单写法：数组
inject: ['theme', 'currentUser']

// 进阶写法：对象 — 可以设默认值、重命名
inject: {
  theme: { default: 'light' },          // 祖先没提供时用 'light'
  appTheme: { from: 'theme' },          // 重命名：注入 theme，但本地叫 appTheme
  currentUser: { default: null }
}
```

### 本项目中的实际应用 — Element UI 的 el-form

你每天都在用 provide/inject，只是没意识到：

```vue
<el-form :model="form" :rules="rules">
  <el-form-item label="工单号" prop="WorkOrderCode">
    <el-input v-model="form.WorkOrderCode" />  ← el-input 怎么知道校验规则？
  </el-form-item>
</el-form>
```

`el-form` 通过 provide 把 `model`、`rules` 传给所有后代 `el-form-item`、`el-input`，中间不管隔多少层都能直接注入。你不需要手动传 props。

### 四种通信方式对比

| 方式 | 层级 | 响应式 | 适用场景 |
|------|------|------|------|
| props / `$emit` | 父子（1层） | ✅ | 明确的父子关系 |
| provide/inject | 祖先↔后代（跨多级） | ⚠️ 需处理 | 组件库内部透传（如 el-form） |
| Vuex | 任意组件 | ✅ | 全局共享状态 |
| eventBus | 任意组件 | ❌ | 轻量事件（本项目已不用） |

### 什么时候用 provide/inject？

| ✅ 适合 | ❌ 不适合 |
|------|------|
| 封装组件库（如 el-form → el-input） | 业务组件间的数据传递 |
| 插件开发 | 可以用 props 搞定的简单场景 |
| 需要跳过中间层的透传 | 数据流向需要清晰可追踪的业务逻辑 |

> **业务代码尽量少用 provide/inject**——数据来源不清晰（不知道是哪个祖先提供的），出了问题很难排查。业务中优先用 props/$emit 或 Vuex。

## 七、自定义 `v-model` — 让组件支持双向绑定

`v-model` 在原生元素上做双向绑定很简单。但如果想让**自定义组件**也支持 `v-model` 呢？

### 原理：v-model 是语法糖

```vue
<!-- 这两行完全等价 -->
<my-input v-model="searchText" />
<my-input :value="searchText" @input="val => searchText = val" />
```

所以只要组件满足两个条件，就能用 `v-model`：
1. 接收名为 `value` 的 prop
2. 发出名为 `input` 的事件（带新值）

### 实现一个带 v-model 的自定义组件

```vue
<!-- ===== 子组件 my-input.vue ===== -->
<template>
  <input :value="value" @input="$emit('input', $event.target.value)" />
</template>
<script>
export default {
  props: ['value']       // ← 接收 value
  // @input 事件发出新值 → 父的 v-model 自动更新
}
</script>

<!-- ===== 父组件 ===== -->
<my-input v-model="searchText" />
<!-- searchText 和输入框内容双向同步 -->
```

### 修改 v-model 默认的 prop 和事件名（Vue 2.2+）

```js
// 子组件
export default {
  model: {
    prop: 'checked',          // 不用 value，用 checked
    event: 'change'           // 不用 input，用 change
  },
  props: ['checked']
}
```

```vue
<!-- 父 -->
<my-checkbox v-model="isChecked" />
<!-- 等价于 :checked="isChecked" @change="val => isChecked = val" -->
```

> 一个组件只能有一个 `v-model`。如果需要多个双向绑定，用 `.sync`。

## 八、`.sync` 修饰符 — 多属性双向绑定

`v-model` 只能绑一个值。`.sync` 可以同时对**多个 prop**做双向绑定。

### 语法

```vue
<!-- 父 -->
<child :visible.sync="dialogVisible" :title.sync="dialogTitle" />

<!-- 等价于 -->
<child
  :visible="dialogVisible" @update:visible="val => dialogVisible = val"
  :title="dialogTitle"     @update:title="val => dialogTitle = val"
/>
```

```js
// 子组件 — 发特定格式的事件
this.$emit('update:visible', false)    // 父的 dialogVisible → false
this.$emit('update:title', '新标题')   // 父的 dialogTitle → '新标题'
```

### 你项目中的实际例子

```vue
<!-- outputindex.vue -->
<pagination
  :page.sync="queryParams.pageIndex"     ← 分页组件内部改 page → 父的 pageIndex 同步更新
  :limit.sync="queryParams.pageSize"    ← 分页组件内部改 limit → 父的 pageSize 同步更新
  :slotcontent.sync="slotContent"       ← 和上面一样
/>
```

> 规则：子组件 `$emit('update:prop名', 新值)`，父组件 `:prop名.sync`。

### v-model vs .sync 对比

| | v-model | .sync |
|------|------|------|
| 数量 | 一个组件只能有一个 | 可以有多个 |
| 默认 prop/event | `value` / `input` | prop 名 / `update:prop名` |
| 语义 | "这是组件的值" | "这个 prop 可以双向同步" |
| 典型场景 | 输入框、选择器 | 弹窗显示、分页参数 |

## 九、一句话总结

> **父子**用 props/`$emit`，**全局**用 Vuex，**兄弟**用 Vuex（不用 eventBus）。
