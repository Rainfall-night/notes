# 组件生命周期钩子

> 基于 MES 前端项目 `STwebsiteFrontEnd_V1` 的实际代码

---

## 一、完整生命周期

```
new Vue() / 组件创建
    │
    ├── beforeCreate    ← data/props/methods 都不可用，几乎不用
    │
    ├── 初始化数据、响应式
    │
    ├── created         ← ✅ data 可访问，适合调 API（DOM 还没生成）
    │
    ├── 编译 template → render 函数
    │
    ├── beforeMount     ← 即将首次渲染，几乎不用
    │
    ├── 创建 vm.$el，挂载到 DOM
    │
    ├── mounted         ← ✅ DOM 已生成，适合操作 DOM、发请求
    │
    ├── (数据变化)
    │
    ├── beforeUpdate    ← 数据已变，DOM 还是旧的
    │
    ├── 重新渲染、diff、patch DOM
    │
    ├── updated         ← DOM 已更新
    │
    ├── (keep-alive 场景)
    │
    ├── activated       ← 从缓存中激活
    ├── deactivated     ← 被缓存起来
    │
    ├── beforeDestroy   ← 销毁前，清理定时器/事件监听
    │
    └── destroyed       ← 组件销毁完成
```

## 二、本项目中实际使用

### ① `mounted` — 最常用

```js
// TEST_LIV/index.vue
mounted() {
    this.initCheckList()
    this.getOptions()
    this.fetchData(this.queryParams)   // 页面加载完就查数据
}
```

> 几乎每个页面都在 `mounted` 中调 `fetchData`。DOM 已挂载，可以安全操作 `this.$refs` 和 `this.$el`。

### ② `activated` — keep-alive 专属

```js
// processingindex.vue
activated() {
    this.initCheckList()
    this.getOptions()
    // this.fetchData()  // 注释掉了，不重新查
}
```

因为被 `<keep-alive>` 缓存的页面，第二次切回来**不会**走 `mounted`，而是走 `activated`。

### ③ `beforeDestroy` — 清理资源

```js
// ResizeHandler mixin
beforeMount() {
    window.addEventListener('resize', this.$_resizeHandler)
}
beforeDestroy() {
    window.removeEventListener('resize', this.$_resizeHandler)
}
```

> `beforeDestroy` 中清理事件监听、定时器、WebSocket，防止内存泄漏。

## 三、关键对比

| 钩子 | 能做什么 | 实际场景 |
|------|----------|----------|
| `created` | data 可用，调 API | 少见，一般用 mounted |
| `mounted` | **DOM 可用**，调 API、初始化 | 页面加载查数据 |
| `updated` | DOM 已更新 | 罕见，容易死循环 |
| `beforeDestroy` | 清理定时器、事件 | ResizeHandler |
| `activated` | keep-alive 页面激活 | processingindex |

## 四、常见坑

1. **`mounted` 中数据还未返回**：API 是异步的，`mounted` 调了 `fetchData` 不等于数据已经到了
2. **`updated` 中改数据 → 死循环**：改数据又触发 `updated`，无限循环
3. **keep-alive 页面用 `mounted`**：第二次切回来不会重新执行，要用 `activated`
