## 一、render 函数 — 用 JS 写模板

模板 (`<template>`) 最终都会被编译成 `render` 函数。`render` 函数让你直接跳过模板，用纯 JS 描述 DOM 结构。

### 模板 vs render 函数

```vue
<!-- 模板写法 -->
<template>
  <div class="wrapper">
    <h1 v-if="level === 1">{{ title }}</h1>
    <h2 v-else>{{ title }}</h2>
  </div>
</template>

<!-- render 函数写法（等价） -->
<script>
export default {
  props: ['level', 'title'],
  render(h) {
    return h('div', { class: 'wrapper' }, [
      h('h' + this.level, this.title)   // 动态标签名！
    ])
  }
}
</script>
```

### `h` 函数（createElement）参数

```js
h(标签名, 属性对象, 子节点数组)
//   ↓        ↓           ↓
h('div', { class: 'box', attrs: { id: 'app' } }, [
    h('span', '文本'),
    h('button', { on: { click: this.handleClick } }, '按钮')
])
```

### render 函数的优势

| 模板 | render 函数 |
|------|------|
| 简单直观 | 灵活，动态性最强 |
| 固定结构优先 | 需要动态决定标签名/结构时 |
| 绝大多数场景够用 | 写高阶组件、函数式组件时 |

> **绝大多数时候不需要 render 函数**。模板足够。render 函数主要用于：动态生成标签名、封装高阶组件、需要完全编程式控制的场景。

### JSX — render 函数的"类模板"写法

JSX 让你用类似 HTML 的语法写 render 函数（需要 babel 插件）：

```jsx
// JSX 写法
render() {
  return (
    <div class="wrapper">
      <h1>{this.title}</h1>
    </div>
  )
}

// 编译后等价于
render(h) {
  return h('div', { class: 'wrapper' }, [
    h('h1', this.title)
  ])
}
```

> 本项目没用 JSX，纯模板写法。JSX 在 React 中是标配，Vue 中完全可选。

## 二、函数式组件（Functional Component）

**没有实例的组件**——没有 `this`、没有 `data`、没有生命周期、没有响应式。纯粹是"props 进去，VNode 出来"的函数。

### 为什么需要函数式组件？

普通组件每个实例都有内存开销（响应式系统、watcher、生命周期钩子）。如果页面上渲染成千上万个简单组件（如列表项），开销很大。函数式组件省掉这些开销——渲染快、内存小。

### 写法

```vue
<template functional>
  <div class="list-item">
    <span>{{ props.title }}</span>           <!-- props 不是 this.props -->
  </div>
</template>

<script>
export default {
  functional: true,     // 标记为函数式组件
  props: ['title']
}
</script>
```

**render 函数写法：**

```js
export default {
  functional: true,
  props: ['title'],
  render(h, context) {
    // context = { props, children, slots, data, parent, listeners, injections }
    return h('div', { class: 'list-item' }, [
      h('span', context.props.title)
    ])
  }
}
```

### 函数式组件的特点

| 有 | 没有 |
|------|------|
| props | `this` |
| slots / scopedSlots | data / computed / watch |
| listeners / attrs | 生命周期钩子 |
| 可以 `inject` | 响应式系统 |
| | `$refs` |

> **适合**：纯展示型组件、列表中的每一项。**不适合**：需要交互逻辑、需要生命周期的组件。

## 三、Vue.extend — 组件构造器

用一个组件选项对象，创建一个"组件类"。然后可以 `new` 它，手动挂载。

```js
import Vue from 'vue'
import Toast from './Toast.vue'

// 创建"Toast 类"
const ToastConstructor = Vue.extend(Toast)

// 需要弹 Toast 时，手动 new 一个实例
function showToast(message) {
  const instance = new ToastConstructor({
    data: { message }
  })
  instance.$mount()                            // 生成 DOM
  document.body.appendChild(instance.$el)      // 插入页面

  // 3 秒后销毁
  setTimeout(() => {
    instance.$destroy()
    document.body.removeChild(instance.$el)
  }, 3000)
}
```

### 什么场景用？

| 场景 | 说明 |
|------|------|
| 命令式弹窗 | 不在模板里写 `<toast />`，用 JS 调 `showToast('成功')` |
| Loading 遮罩 | `this.$loading.show()` 然后 `this.$loading.hide()` |
| 消息提示 | Element UI 的 `this.$message('成功')` 就是这么实现的 |

> 正常业务开发基本不用。Element UI 等组件库底层用它。如果你要封装一个"用 JS 调用的弹窗/Loading/Toast"，才需要 `Vue.extend`。

## 四、递归组件 — 组件自己调用自己

树形结构（菜单、文件夹、评论嵌套）需要一个组件渲染自身。

### 实现

```vue
<!-- TreeItem.vue -->
<template>
  <div class="tree-item">
    <div class="label">{{ item.name }}</div>
    <!-- 如果有子节点，递归渲染自己 -->
    <tree-item
      v-for="child in item.children"
      :key="child.id"
      :item="child"
    />
    <!--      ↑ 组件在自己的模板里用自己 -->
  </div>
</template>

<script>
export default {
  name: 'TreeItem',        // ← 必须有 name！否则自己认不得自己
  props: ['item']
}
</script>
```

### 关键要求

1. **必须有 `name` 选项** —— 组件通过 `name` 在自己的模板中引用自己
2. **必须有终止条件** —— 没有 `children` 时停止递归，否则无限循环爆栈

### 本项目中的潜在场景

你的项目中有左侧菜单（Sidebar），它的 `MenuItem` 组件就是递归组件——菜单项有子菜单时递归渲染自己。

## 五、异步组件 — 按需加载

正常 `import` 是**同步**的，打包后全在一个 JS 文件里。异步组件让"用到时才加载"，减小首屏体积。

### 三种写法

```js
// 写法一：简单工厂函数（Vue 2 基础写法）
const AsyncComp = () => import('./HeavyComponent.vue')

// 写法二：带加载状态
const AsyncComp = () => ({
  component: import('./HeavyComponent.vue'),
  loading: LoadingComponent,     // 加载中显示
  error: ErrorComponent,         // 加载失败显示
  delay: 200,                    // 200ms 后才显示 loading
  timeout: 3000                  // 3 秒超时
})

// 写法三：路由懒加载（你项目里就在用！）
{
  path: '/report/outputindex',
  component: () => import('@/views/report/outputindex')
  //           ↑ 只有访问这个路由时，才加载这个组件的 JS
}
```

### 路由懒加载 — 你每天都在用

```js
// router/index.js
{
  path: '/TEST_LIV',
  component: () => import('@/views/TEST_LIV/index')
  //          ↑ 异步组件 + webpack 代码分割
  //          → 打包成独立的 chunk 文件
  //          → 用户访问 /TEST_LIV 时才下载
}
```

**效果：** 用户打开首页时只下载首页的 JS（几百 KB），而不是整个系统（几十个页面加起来可能几十 MB）。访问哪个页面才下载哪个页面的代码。

### 异步组件 vs 同步组件

| | 同步组件 | 异步组件 |
|------|------|------|
| 加载时机 | 打包进 app.js，首页全加载 | 用到时才加载 |
| 首屏体积 | 大 | 小 |
| 适用 | 首页、公共组件 | 非首屏页面、弹窗 |
| 写法 | `import Comp from '...'` | `() => import('...')` |

> 你在 `router/index.js` 中写的 `component: () => import(...)` 就是异步组件——这是 Vue 项目的标配做法。
